# CLAUDE.md — карта репозитория biblio для Claude Code

**Правила** проекта — в [`AGENTS.md`](AGENTS.md): это единственный канонический источник,
общий для всех агентов. Прочитай его полностью перед любым действием. Здесь — только
**карта кода и рабочие процедуры**, которых в AGENTS.md нет; конфликт трактуется в
пользу AGENTS.md.

Claude-специфичные команды — в `.claude/commands/`, безопасные разрешения — в
`.claude/settings.json` (оба в Git). Локальные разрешения — только в игнорируемом
`.claude/settings.local.json`.

## Красные линии (выжимка; полностью и с обоснованием — в AGENTS.md)

- Ветка по умолчанию — **`master`**. Прямой push в `master`, `--force`, `reset --hard`
  запрещены (`.claude/settings.json` их и не пропустит). Только: ветка → PR → squash.
- `../brain_matrica` — **read-only**. Никаких `fetch`/`pull`/`checkout`/записи туда.
- Репозиторий **публичный**: хостнеймы, IP, SSH-алиасы, порты, серверные пути, имя
  хостера — не попадают в трекаемые файлы вообще, включая доки и письма.
- Legacy-код (корень, `moduls/`, `history_postopus/`, `sumatra/`, `instructions/`) —
  музей: не рефакторить и не «чинить» попутно.
- Финальные ответы владельцу — по-русски; идентификаторы и commit messages — по-английски.

## `tools/` — как устроены desktop-утилиты

Три утилиты, все под Windows, все работают оффлайн:
[audio-to-text](tools/audio-to-text/) (речь → текст, GigaAM v2 + Silero, CPU),
[video-downloader](tools/video-downloader/) (страница → все видео, yt-dlp),
[net-monitor](tools/net-monitor/) (трей: интернет/VPN/DNS/канал Claude Code, PowerShell).

**Каркас Python-утилиты** — повторяй его для новых:

```
tools/<имя>/
  <ядро>.py         CLI-ядро: работает само, из командной строки, без GUI
  gui.py            tkinter-обёртка, импортирует функции ядра (не дублирует логику)
  install.ps1       создаёт .venv, ставит requirements; идемпотентен
  run.ps1           запускает gui.py из .venv (pythonw, чтобы не мигала консоль)
  Запустить.cmd     двойной клик для владельца → run.ps1
  requirements.txt  с комментариями, почему пакет тут и что делать, если падает
  README.md         для владельца: установка, запуск, что делает
  .gitignore        .venv/, __pycache__/, модели, логи, выходные файлы
```

Ключевое разделение: **ядро самодостаточно, GUI — тонкий слой**. `download.py`
экспортирует `download_urls(...)` с колбэками `log`/`progress`; `gui.py` только зовёт её.

`net-monitor` — PowerShell, устроен иначе: `net-monitor.ps1` (трей и UI) + `lib/probe.ps1`
(чтение состояния) + `lib/recovery.ps1` (лестница восстановления) + `install.ps1` +
`build-package.ps1` (архив для передачи людям).

## Локальные проверки (CI нет)

В репозитории **нет `.github/`, нет тестов и линтеров** — гейт только ручной. Минимум
перед коммитом:

```bash
python -m py_compile tools/<инструмент>/*.py          # Python: синтаксис
pwsh -NoProfile -Command '[System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path ./tools/net-monitor/net-monitor.ps1), [ref]$null, [ref]$e); $e'
```

Специфика `net-monitor` (полноценно проверяется только на Windows): `-Once` — разовый
прогон проверок в консоль, `-SelfTest` — печатает выбранные шаги восстановления, ничего
не меняя; `build-package.ps1` дополнительно **проверяет склейку однофайловой сборки
парсером**. Среда агента — Linux, так что реальный прогон трея и установщика — на
владельце; не заявляй «проверено», если проверял только парсер.

## Конвенции, которые уже стоили сессии

- **`.ps1` — UTF-8 с BOM.** Запуск идёт через `powershell` 5.1: без BOM файл читается как
  ANSI, кириллица ломается, скрипт молча перестаёт работать. Проверяй после каждого
  создания/перезаписи файла.
- **`.cmd` — ASCII без BOM**, комментарии в них по-английски.
- Консольному PowerShell-скрипту с русским выводом нужен явный
  `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`.
- **Версия артефакта — из одного места.** У `net-monitor` это `$AppVersion` в
  `net-monitor.ps1`; сборщик и установщик читают её оттуда регуляркой (не dot-source:
  выполнять чужой файл ради константы нельзя). Версия видна в меню трея, логе и имени
  архива — иначе баг-репорт непроверяем.
- **Умолчания рассчитаны на чужую машину**: всё, что меняет систему (смена DNS,
  перезапуск VPN/адаптера), поставляется выключенным.
- **Измерение не делит ресурс с отрисовкой.** Пробы у `net-monitor` живут в фоновом
  runspace с очередью; UI-поток только забирает готовое. Стоимость проверки максимальна
  ровно в аварии — в тот единственный момент, ради которого утилита нужна.
- Комментарии в коде объясняют **почему**, а не что; в `tools/` они по-русски, в
  служебных launcher-скриптах — по-английски.
- Тяжёлое (venv, модели, бинарники, собранные архивы) — в `.gitignore` каждого
  инструмента, в Git не попадает.

## Рабочий процесс сессии

Исполняемые памятки лежат в `.claude/commands/` и применимы к любому агенту:

| Команда | Когда |
|---|---|
| [`/start`](.claude/commands/start.md) | Начало: sync только своего репо → проверка `from-brain` → `docs/SESSION_HANDOFF.md` |
| [`/close_session`](.claude/commands/close_session.md) | Конец значимой работы: письмо Мозгу (если есть инсайт) → handoff → PR → sync-гейт |
| [`/obriv`](.claude/commands/obriv.md) | После обрыва: восстановить картину из git/PR, не по памяти чата |

Порядок в `/start` жёсткий: **сначала синхронизация, потом чтение session-памяти**.
Отсутствие канала `../brain_matrica/mailboxes/biblio/from-brain/` — норма, не ошибка.

**Git-поток:** ветка `feat/ fix/ chore/ docs/` → Conventional Commits → `git push -u origin
<ветка>` → PR → squash merge → `git checkout master && git pull --ff-only`. Один PR — одна
задача. При параллельной работе нескольких агентов — отдельный `git worktree`; незнакомые
изменения в дереве чужие: не удалять, не форматировать, не включать в свой коммит.

**Про `gh`:** памятки написаны под `gh` CLI. В веб-сессиях Claude Code его нет — те же
операции делаются GitHub MCP-инструментами (`mcp__github__*`); смысл шагов не меняется.

## Память и коммуникация

- [`docs/SESSION_HANDOFF.md`](docs/SESSION_HANDOFF.md) — состояние между сессиями:
  **Статус**, **Сделано** (с абсолютными датами), **Следующий шаг**, **Открытые вопросы
  владельцу**, **Грабли и инсайты**. Обновляй в конце значимой работы.
- [`docs/superpowers/specs/`](docs/superpowers/specs/) — дизайн-документы под крупные
  доработки: постановка от владельца, факты разведки, принятые решения. Пиши сюда до
  реализации, если задача больше одной сессии.
- [`mailbox/to-brain/`](mailbox/) — письма Мозгу, `YYYY-MM-DD-slug.md` с frontmatter
  (`from`, `to`, `date`, `kind`). Канала на brain-стороне пока нет: письма копятся здесь,
  тишина в ответ — норма. Писать в `../brain_matrica/` нельзя никогда.
- Переносимый инсайт (не про конкретную утилиту, а про устройство систем) → письмо Мозгу;
  локальная грабля → раздел «Грабли и инсайты» в handoff.

## Про музей — чтобы не потратить сессию зря

Почти весь старый код **не запускается**: он завязан на отсутствующие в репо `config.py` /
`bases/logpass.py` (там жили секреты) и на API 2019–2021 годов — парольная авторизация VK
закрыта, `instabot` заблокирован, `Image.ANTIALIAS` удалён в Pillow 10. Корневой
`requirements.txt` описывает именно эту мёртвую половину и к `tools/` отношения не имеет.
Доделка утилиты — осознанная задача сессии с явной просьбой владельца, а не попутная
уборка. Legacy-файлы могут содержать протухшие секреты: не копируй их содержимое в новые
файлы, письма и документацию; находку — доложи владельцу.
