# ocvpn — локальный VPN-контроллер для OpenCode

Программа поднимает на этой машине туннель, заворачивает в него **только трафик OpenCode**
и умеет менять сетевую личность на лету — без перезапуска движка и без разрыва сессии.

Один файл на Python (стандартная библиотека), ядро — `sing-box`. Ни venv, ни pip.

## Зачем

Free-тир OpenCode считает **сообщения за сутки на сеть** ([G497](../../../brain_matrica/cross-project-ideas/gotchas/G497.md)).
Когда лимит выбран, смена модели не помогает — помогает смена адреса, с которого приходит запрос.
Переключение живёт на уровне прокси: адрес `127.0.0.1:18080` для OpenCode не меняется никогда,
поэтому ротация занимает секунды и ничего не рвёт.

## Как устроено

```
Запустить.cmd
  └─ ocvpn.py
       ├─ ocvpn-core.exe (sing-box)  ── mixed :18080 ── clash_api :19090
       ├─ opencode serve :18082       (HTTPS_PROXY=127.0.0.1:18080)
       └─ дашборд :18081              (кнопки, лента, счётчики)
```

- Ядро держит пул нод (VLESS/Reality, Hysteria2, TUIC, Trojan, Shadowsocks, VMess) одним
  селектором; ротация = `PUT /proxies/auto`, то есть переключение исходящего внутри ядра.
- Сторож не тратит квоту на наблюдение: он читает **лог самого OpenCode**
  (`%USERPROFILE%\.local\share\opencode\log\opencode.log`) и реагирует на строку
  `Free usage limit reached`. Синтетических опросов по таймеру нет.
- Проба — один реальный запрос модели на 1 сообщение. Она же проверяет, жива ли квота
  на новой сети: **провал пробы квоту не тратит** (сеть и так пустая).

## Правда о бесплатных нодах (замер 26.10.2026)

Проверено на PC79 в два прохода. Второй — широкий, потому что первый был смещён
(6 из 9 проверенных нод принадлежали одному фермерскому пулу):

| Замер | Вход | Живых | Проверено пробой | Дали квоту |
|---|---|---|---|---|
| №1 | 4 источника → 400 нод | 63 | 9 нод, 4 провайдера | 0 |
| №2 | **12 источников → 1500 нод** | 183 (12 %) | **40 нод, 21 разная /24, 5 протоколов** | **0** |

В замере №2: 35 нод дошли до API и все 35 ответили `Free usage limit reached`
(vless 9, trojan 10, ss 9, hysteria2 4, vmess 3), 4 — обрыв, 1 — таймаут. При этом
**контроль без прокси и через Happ отвечал и до, и после прогона** — квота у аккаунта
была жива, ограничение именно адресное.

Причина: квота считается по сети, а публичные бесплатные ноды — ровно тот пул, которым
пользуются все, кто жмёт free-тир. Адрес «свежий» для нас, а квота на нём уже чужая.
Это тот же класс отказа, что P210 у Сарафана.

Практический вывод: годен только выход, которым **больше никто не пользуется** — поэтому
личный Happ квоту даёт, а 21 сервер общей подписки нет. Публичные списки как источник
сброса не работают; инструмент остаётся контроллером и сборщиком проверок
(«даёт ли этот адрес квоту прямо сейчас»).

## Команды

| Команда | Что делает |
|---|---|
| `Запустить.cmd` | поднять ядро + OpenCode + дашборд и открыть браузер |
| `py -3 ocvpn.py doctor` | проверки окружения: python, ядро, opencode, лог, Happ, прямой IP |
| `py -3 ocvpn.py refresh` | обновить списки нод |
| `py -3 ocvpn.py check` | проверить ноды задержкой, оставить живые |
| `py -3 ocvpn.py rotate` | переключиться на следующую ноду |
| `py -3 ocvpn.py probe` | один реальный запрос модели (стоит 1 сообщение) |
| `py -3 ocvpn.py status` | состояние в JSON |
| `py -3 ocvpn.py happ-off` / `happ-on` | остановить/запустить службу Happ (UAC) |
| `py -3 ocvpn.py install` / `uninstall` | автозапуск при входе в систему |

## Дашборд

`http://127.0.0.1:18081` — состояние, нода, внешний IP, модель, счётчики (ротации, пробы,
лимиты), лента событий и кнопки: ротировать, собрать свежую сеть, проверить ноды, обновить
списки, проба, сменить модель, рестарт OpenCode, выключить/вернуть Happ, старт/стоп.

## Ядро

`core/ocvpn-core.exe` — копия `sing-box` 1.12.12 (берётся из установки Happ, в git не кладётся).
Нужна сборка с `with_clash_api` и `with_quic`. Проверка: `core\ocvpn-core.exe version`.

Списки нод несут xray-отпечаток `fp=unsafe`, которого sing-box не знает: ядро падает на
нём с `unknown uTLS fingerprint: unsafe`, и такие ноды выкидывались из пула молча.
При сборке конфига незнакомые отпечатки заменяются на `chrome`.

## Про Happ

Happ держит маршрут по умолчанию на свой туннель и `DIRECT` не выводит трафик мимо своего
стека. На внешний IP это не влияет (выход определяет наша нода, а не Happ), но добавляет
лишний слой до ноды. Кнопки выключения/возврата службы поднимают UAC: `HappService` —
служба Windows, без прав её не остановить.

## Чего здесь нет

- TUN и правки маршрутов (нужны права администратора — не наша модель).
- Прямого трафика OpenCode мимо туннеля: упало ядро — движок не поднимается (fail-closed).
- Платных ключей и приватных данных через бесплатные ноды: списки чужие.
- Второго транспорта. Reality-ноды, которые берёт xray и не берёт sing-box
  (`reality verification failed` в `state/core.log`), утилите недоступны: подменить ядро
  на лету она не умеет. Проверено на своём сервере и на публичной ноде — sing-box 1.12.12,
  1.14.4 и 1.15.0-alpha.13 отказывают одинаково, `flow`/`fp` тут ни при чём. Reality как
  протокол при этом работает: живые reality-ноды в пуле проходят проверку.
