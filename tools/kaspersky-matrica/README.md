# kaspersky-matrica — настройка Касперского под «Матрица РМЗ»

Инструмент + **модуль сопровождения**: программа Матрицы меняется (пути, адрес сервера,
новые компоненты), и список исключений обязан меняться вместе с ней. Здесь — и утилита,
и правила её поддержки.

**Запуск:** `Запустить.cmd` · для кнопок «Сохранить/Применить эталон» —
`Запустить-от-администратора.cmd`.

## Что он делает

1. **Находит сам** на текущем компьютере: Касперского (редакция, версия, `avp.com`),
   клиент Матрицы, сторож, папки данных/обновлений, адрес прод-сервера и его IP.
2. **Показывает готовые строки** для внесения в Касперский — каждая с кнопкой
   «Копировать» (и «Копировать всё»).
3. **Рендерит инструкцию** под реальные пути → `%LOCALAPPDATA%\kaspersky-matrica\`.
4. **Экспорт/импорт эталона настроек** Касперского (`avp.com EXPORT/IMPORT`) — штатный
   способ перенести конфигурацию на другие компьютеры.
5. **Проверяет состояние** (`-Verify`): цел ли клиент, цел ли сторож, на месте ли
   плановые задачи, свежо ли рукопожатие, отвечает ли сервер.

## Режимы

| Команда | Что |
|---|---|
| `kaspersky-matrica.ps1` | окно с готовыми строками (основной режим) |
| `-Quiet` | то же в консоль |
| `-Json` | машинный вывод — для встраивания в Матрицу/сторож |
| `-Verify` | проверка состояния |
| `-Export <файл.cfg>` | сохранить эталон настроек Касперского (нужен админ) |
| `-Import <файл.cfg>` | применить эталон (нужен админ) |
| `-SettingsPassword <пароль>` | если в Касперском стоит пароль на управление настройками |
| `-Report <путь.md>` | куда положить отрендеренную инструкцию |

## Граница возможного — читать до того, как просить «сделай полностью автоматически»

Проверено замером (Kaspersky Standard 21.26) и по документации Касперского:

- **Команды «добавить исключение» у потребительского Касперского НЕТ.** `avp.com HELP`
  даёт: HELP, SCAN, UPDATE, ROLLBACK, RENEW, FEATUREFLAGS, START, STOP, STATUS,
  STATISTICS, **EXPORT**, **IMPORT**, AcceptEULA, REPORT, SHOWTM, PROXYAUTH, EXIT, TRACES.
  Ни EXCLUSION, ни TRUSTED, ни ADD. Исключения создаются только в окне программы.
- **Подсунуть файл настроек в папку Касперского нельзя.** Конфиг непрозрачный, а
  **Самозащита** — отдельный механизм: она **не выключается** вместе с защитой в реальном
  времени и блокирует правку файлов/реестра/процессов Касперского извне в любом состоянии
  защиты. Идея «программа настроит Касперского, пока он спит» не реализуема в принципе —
  это не обход лени, это защищённая граница продукта.
- **Что автоматизируемо:** определение путей, генерация строк, инструкция и
  **EXPORT/IMPORT всей конфигурации**. Последнее и есть «скрипт настройки для других
  компьютеров», о котором шла речь — с двумя условиями: одинаковая версия Касперского и
  понимание, что импорт заменяет **все** настройки, а не добавляет одну программу.
- **Прочитать список действующих исключений программно тоже нельзя** — поэтому `-Verify`
  честно отвечает «всё ли цело и работает», а не «внесены ли исключения». Не завышать
  это в отчётах.

Если когда-нибудь потребуется настоящая централизованная раскатка — это Kaspersky
Endpoint Security + Security Center (бизнес-линейка): там исключения задаются политикой
на группу машин и разъезжаются сами, плюс есть импорт/экспорт доверенной зоны в XML.
На потребительской линейке такого нет by design.

## Что именно вносится (и почему каждый пункт)

| Что | Зачем |
|---|---|
| `MatricaRMZ.exe` → доверенная программа | снимает поведенческий контроль и контроль сети с клиента |
| `matricarmz-watchdog.exe` → доверенная программа | **самый уязвимый** файл: неподписанный Go-бинарь по расписанию — типовой ложный вердикт эвристики |
| папка приложения | файлы клиента не сканируются на каждом открытии |
| папка сторожа | то же + не даёт «свипу» унести бинарь |
| `%APPDATA%\MatricaRMZ` | рукопожатие, состояние и локи сторожа |
| `%APPDATA%\@matricarmz` | **рабочие данные клиента: база SQLite, логи, файл ключа** — самая пишущая папка; без неё исключения выглядят полными, а тормоза остаются |
| папка обновлений | туда качается установщик (`MatricaRMZ-Setup-*.exe`) — свежий неподписанный установщик антивирусы трогают чаще всего |
| IP прод-сервера : 443 | чтобы проверка трафика не рвала обмен с сервером |

## Модуль сопровождения: когда обновлять инструмент

Инструмент читает пути **из самого приложения** (рукопожатие
`%APPDATA%\MatricaRMZ\watchdog.json`: `appExePath`, `userDataDir`, `updatesRootDir`,
`apiBaseUrl`), поэтому переезд путей и смена адреса сервера подхватываются **сами**.
Править инструмент нужно, когда:

1. **Появился новый исполняемый компонент** (ещё один агент, служба, CLI) → добавить его
   в `Get-ExclusionPlan` (`TrustedApps`).
2. **Появилась новая папка, куда приложение активно пишет** → добавить в `$folders` там же.
3. **Изменилась схема рукопожатия** (переименовали поля) → поправить `Get-MatricaInfo`.
4. **Сменился прод-адрес по умолчанию** → `$DefaultApiBaseUrl` / `$KnownProdIps` в шапке
   (это лишь запасной путь: обычно адрес приходит из рукопожатия).
5. **Обновился Касперский до новой мажорной версии** → перепроверить `avp.com HELP`
   (не появилось ли управление исключениями) и перевыпустить эталонный `.cfg` — старый
   в новую версию импортируется с потерями.

После правки — прогнать: `-Quiet` (пути), `-Verify` (состояние), `-Json` (контракт),
и обязательно проверить синтаксис скрипта парсером (см. ниже).

## Технические грабли этого инструмента (пойманы при сборке)

- **`.ps1` обязан быть с BOM.** Windows PowerShell 5.1 читает UTF-8 без BOM как cp1251 —
  кириллица в строках ломает **парсер**, скрипт не запускается вовсе. `.cmd` наоборот —
  **без BOM** и только ASCII (cmd.exe давится BOM в первой строке).
- **`"$target:443"` в PowerShell — не то, что кажется:** двоеточие после имени переменной
  разбирается как указание области видимости, и подстановка молча даёт пустоту. Правильно
  `"$($target):443"`. Поймано на живом выводе (`Связь с сервером ():`).
- **Приложение отдаёт `userData` с прямым слэшем** (`...\Roaming\@matricarmz/electron-app`
  — слэш приходит из имени npm-пакета). Windows такой путь откроет, а Касперский сверяет
  строку исключения **текстом** — правило молча не совпало бы. Инструмент нормализует
  слэши и схлопывает путь к папке-вендору `@matricarmz`, чтобы одно исключение накрыло и
  `electron-app`, и его CDP-двойники от смоука.
- **Маски вместо путей для эталона.** Путь содержит имя пользователя; на другом компе он
  не совпадёт. Для эталонного `.cfg` вносятся маски `C:\Users\*\...`.

## Встраивание в клиент / сторож

Режим `-Json` — готовый контракт: `{ kaspersky, matrica, plan, canAutoApply:false,
autoApplyReason }`. Клиент может вызвать его при старте (или пунктом «Диагностика») и,
если Касперский найден, показать своё модальное окно с теми же строками и кнопкой
копирования.

Три границы, которые нельзя переступать в реализации:

- **не менять настройки Касперского из кода** — Самозащита это заблокирует, а попытка
  выглядит как атака на антивирус;
- **не писать «исключения настроены/проверены»** — прочитать действующий список
  программно нельзя, честная формулировка: «файлы на месте, задачи есть, сервер отвечает»;
- `canAutoApply` в контракте **всегда false** — это не заглушка на будущее, а вывод из
  устройства продукта.

Ещё одна деталь на будущее: `-SettingsPassword` передаётся в `avp.com` обычным аргументом
командной строки, а значит виден в списке процессов любому локальному пользователю.
Для домашней машины это приемлемо; если инструмент когда-нибудь поедет в среду с
несколькими пользователями — читать пароль из защищённого ввода, а не из параметра.
