# net-monitor — «жив ли интернет и работает ли Claude Code» в трее

Трей-утилита для Windows 11 (значок рядом с часами). Чистый PowerShell, **ничего не
устанавливает** — ни Python, ни библиотек. Заказана владельцем 2026-08-26; в тот же день
дополнена контролем канала Claude Code и автовосстановлением связи.

## Что показывает

- **Кружок в трее**: 🟢 всё работает · 🟠 частично (молчит DNS, лёг туннель или не
  отвечает канал до Anthropic) · 🔴 связи нет.
  **Синее кольцо** = активен VPN. **Красное кольцо** = авария выхода: сменилась страна
  или трафик пошёл мимо туннеля.
- **Наведи мышь** — скорость ↓/↑, VPN со страной выхода, состояние канала Claude Code
  (`CC:ok 800мс` / `CC:НЕТ`).
- **Всплывашка** при пропаже и возврате связи, отдельно — при потере канала Claude Code,
  и громкая тревога при смене страны выхода.

## Канал Claude Code — зачем это здесь

Главный вопрос, ради которого утилита затевалась: **Claude завис сам или отвалился
интернет?** Ответ даёт пункт меню «Канал Claude Code…».

Обычные способы проверки в этой конфигурации **врут**, и утилита их не использует:

- **ping не годится**: TUN-драйвер VPN отвечает на ICMP сам — `api.anthropic.com`
  «пингуется» за 0 мс даже когда канал мёртв;
- **счёт соединений не годится**: Claude Code ходит не напрямую, а через локальный
  прокси VPN-клиента, и его сокеты к `127.0.0.1` остаются живыми при полном обрыве.

Работают три честных признака:

1. **Проба тем же путём** — запрос к `api.anthropic.com` через тот самый прокси, которым
   ходит Claude Code. Ответ `HTTP 401` и есть успех: он доказывает, что весь путь
   TCP → TLS → HTTP работает. Ключ не нужен, ничего секретного не отправляется.
2. **Счётчики трафика ядра VPN** — сколько байт прошло через порт Claude Code, сколько
   через туннель и сколько **мимо** туннеля (последнее — утечка).
3. **Страна выхода** — сверяется с ожидаемой (по умолчанию `DE`).

Из них складывается прямой вердикт: «работает, токены идут», «канал жив, но обмена нет —
значит дело не в сети», или «сеть: канал не отвечает, Claude ждёт впустую».

## Автовосстановление интернета

**По умолчанию выключено.** Включается галкой «Восстанавливать интернет автоматически».

Утилита сначала ждёт (по умолчанию 10 с — вдруг вернётся само), затем действует **по
классу поломки**, а не проходит все шаги подряд:

| Что случилось | Что делает |
|---|---|
| Молчит DNS | Сбрасывает кэш DNS → возвращает сохранённые настройки → при лежащем туннеле ставит рабочие DNS на физический адаптер |
| Лёг туннель VPN | Сбрасывает кэш DNS → *(если разрешено)* перезапускает службу VPN |
| Не отвечает канал до Anthropic | То же самое |
| Нет связи вообще | *(если разрешено)* перезапускает адаптер, затем службу VPN |
| Сменилась страна выхода / утечка мимо туннеля | **Ничего.** Останавливается и зовёт владельца — это не её решение |

Перед первой поломкой утилита запоминает **рабочую конфигурацию** (когда всё здорово
три проверки подряд) и, если лестница не помогла, возвращает её. Снимок помечен
отпечатком сети — в другой сети он не применяется, чтобы не прописать чужие адреса.

### Про смену DNS при включённом VPN — честный ответ

Смена DNS помогает **только когда туннель уже лежит** и машина работает напрямую. Пока
туннель жив, системный DNS в цепочке не участвует: имена резолвит само ядро VPN своим
DoH, а «интерфейс маршрута по умолчанию» — это сам туннель, чью настройку клиент
перезапишет при следующем переподключении. Поэтому эта ступень стоит под условием, а не
выполняется «на всякий случай».

### Чего утилита не сделает никогда

Это запрещено в коде, а не настройкой, и снимается только правкой исходника:

- **менять метрики маршрутов в пользу физического адаптера** — это «чинит интернет»,
  молча уводя выход на домашний адрес: вы видите рабочую сеть, а сервер на том конце
  видит другую страну;
- **включать IPv6** — туннель его не несёт, включение создаёт путь мимо туннеля;
- **`netsh winsock reset` / `netsh int ip reset`** — отката нет;
- **перезапускать туннельный адаптер** напрямую — им владеет ядро VPN;
- **трогать конфиги VPN-клиента и переключать сервер или подписку** — смена страны
  остаётся решением владельца.

Перезапуск VPN и адаптера разрешаются отдельными галками и по умолчанию запрещены:
оба рвут все соединения, а при переподключении клиент **может выбрать другой узел**.
Утилита сверяет страну до и после и при расхождении сразу останавливается — но
предотвратить сам выбор она не может.

## Меню (правый клик по значку)

| Пункт | Что делает |
|---|---|
| Статус сети… | Интернет, интерфейс выхода, VPN, DNS, канал Claude Code, выход и страна, интерфейсы |
| Канал Claude Code… | Вердикт «Claude завис или сеть отвалилась», трафик за последние секунды, утечка мимо туннеля |
| Через что идёт сайт… | Вводишь `гоньба.рф` — «пойдёт ЧЕРЕЗ VPN» или «НАПРЯМУЮ» (по таблице маршрутов) |
| Тест DNS-серверов… | Меряет текущие + Yandex/Google/Cloudflare/Quad9/AdGuard/OpenDNS; «Поставить выбранный», «Вернуть автомат (DHCP)» |
| Авто-тест DNS раз в час | Галка: раз в час тест и установка лучшего (нужны права администратора) |
| Восстанавливать интернет автоматически | Галка: включает лестницу выше |
| …что при этом разрешено | Подменю: перезапуск VPN, перезапуск адаптера, ожидаемая страна выхода |
| Починить сейчас (разово)… | Показывает, что будет сделано, и выполняет после подтверждения |
| Автозапуск при входе | Галка: автозагрузка текущего пользователя (HKCU\\...\\Run) |
| Перезапустить от администратора | Без прав администратора шаги восстановления и смена DNS пропускаются |

## Запуск

`Запустить.cmd` (двойной клик). Диагностика одним прогоном без трея:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/net-monitor/net-monitor.ps1 -Once
```

Проверка логики восстановления — печатает, какие шаги были бы выбраны, **ничего не меняя**:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/net-monitor/net-monitor.ps1 -SelfTest
```

## На машине без VPN и без Claude Code

Утилита рассчитана и на чужой компьютер, поэтому **не предполагает наличия ничего**:

- **нет VPN** — контроль туннеля выключается сам, значок зелёный, в статусе пишется
  «VPN не обнаружен». Отсутствие туннеля не считается поломкой;
- **VPN другой** (WireGuard, OpenVPN, штатный клиент Windows) — туннель определяется по
  адаптеру, а не по имени процесса, поэтому живой туннель не объявляется мёртвым;
- **нет Claude Code** — проверка его канала не выполняется вовсе, пункт меню скрыт;
- **страна выхода** по умолчанию не контролируется. При первом запуске, если VPN найден,
  утилита один раз спросит, следить ли за текущей страной.

Режимы можно задать вручную в `config.json`: `vpnMode` и `claudeMode` — `auto` / `on` /
`off`, `expectedCountry` — код страны или пусто.

## Как передать другому человеку

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/net-monitor/build-package.ps1
```

Собирает `net-monitor.zip` (~42 КБ) и печатает SHA256. По умолчанию `lib/*.ps1`
склеиваются внутрь основного скрипта: в архиве четыре файла без вложенных папок, так
что потерять `lib` при распаковке невозможно. Ключ `-Folder` оставляет модули
раздельными — удобнее для правок, но требует аккуратной распаковки.

Получателю: распаковать (именно распаковать) и запустить `Запустить.cmd`. Внутри архива
лежит [ДЛЯ-ПОЛУЧАТЕЛЯ.txt](ДЛЯ-ПОЛУЧАТЕЛЯ.txt) — что это, что делает, как посмотреть
своими глазами, ничего не меняя.

**Почтой не отправится:** Gmail и Outlook режут `.cmd` даже внутри архива. Telegram,
облачный диск или git — подойдут.

### Почему не .exe

Соблазнительно, но для **этой** утилиты вредно. Она меняет DNS, умеет перезапускать
адаптер и службу VPN, просит права администратора и живёт в трее — это в точности тот
поведенческий профиль, по которому антивирусы ищут угрозы. В виде скриптов поведение
приписывается подписанному `powershell.exe`; завёрнутое в самодельный неподписанный
`.exe`, оно получает к тому же подозрительную упаковку и нулевую репутацию у SmartScreen
(накопить её нельзя: хеш меняется с каждой сборкой, подписи нет). Типичный исход —
файл молча исчезает в карантине, и получатель решает, что вы прислали вирус.

Второе, более важное: `.exe` превращает утилиту в чёрный ящик. Человек, которому
предлагают запустить от администратора программу, переписывающую сетевые настройки,
вправе прочитать, что она делает, и прогнать `-Once` и `-SelfTest`, ничего не меняя.
Скрипты это позволяют, скомпилированный `.exe` — нет.

Если нужен ярлык в «Пуске» и постоянный путь установки, разумная середина — установщик
Inno Setup: он оставляет `.ps1` читаемыми на диске и лечит проблему автозапуска с
временного пути. Самораспаковывающиеся архивы (IExpress, 7-Zip SFX) не годятся: они
раскладываются во временную папку, и «автозапуск при входе» сохранит путь, который
Windows однажды вычистит.

## Устройство

| Файл | Что внутри |
|---|---|
| `net-monitor.ps1` | Трей, меню, окна, таймеры |
| `lib/probe.ps1` | Индикаторы состояния. **Только читает** — ни одной команды, меняющей систему |
| `lib/recovery.ps1` | Лестница восстановления, снимок рабочей конфигурации, откат, стоп-лист запретов |
| `build-package.ps1` | Сборка архива для передачи |
| `ДЛЯ-ПОЛУЧАТЕЛЯ.txt` | Инструкция для человека, которому утилиту прислали |

⚠️ Файлы `.ps1` обязаны сохраняться в **UTF-8 с BOM**: утилита запускается через
`powershell` 5.1, который без BOM читает файл как ANSI — кириллица ломается, и скрипт
перестаёт работать целиком. `Запустить.cmd` — наоборот, ASCII без BOM: `cmd.exe` не
понимает BOM, а кириллица в нём читается в OEM-кодировке.

## Границы и честные оговорки

- **Смена DNS — системная настройка**: без прав администратора каждое применение
  спросит UAC-окно; авто-режим без прав молча пропускает применение (пишет в лог).
- **Якоря «интернет жив» — только крупные хосты** (`77.88.8.8`, `1.1.1.1`, `ya.ru` по
  TCP:443): в некоторых сетях фильтрация режет мелкие сайты при живом интернете —
  иначе были бы ложные «нет интернета».
- **Вердикт «через VPN / напрямую» — по таблице маршрутов** на момент проверки. Split-tunnel
  и правила самого VPN-клиента поверх маршрутов (например, обход по списку доменов
  внутри клиента) утилита видеть не может — она отвечает за то, что решает ОС.
- Скорость считается по интерфейсу маршрута-по-умолчанию; при активном VPN это обычно
  туннель (то, что реально видит приложение).
- Лог: `%LOCALAPPDATA%\net-monitor\log.txt`; настройки: `config.json` там же.

## Если хочется готового вместо/рядом

- [NetSpeedTray](https://github.com/erez-c137/NetSpeedTray) (open source) — красивые
  скорости прямо на панели задач; но без VPN/DNS-логики.
- [DNS Jumper](https://www.sordum.org/7952/dns-jumper-v2-3/) (Sordum, портативный) —
  зрелый тест+смена DNS («Turbo Resolve» ставит быстрейший при старте); но без трея,
  мониторинга и VPN.
- GRC DNS Benchmark — эталонный замер DNS, но ничего не ставит сам.

Наш инструмент — именно «всё в одном взгляде»; эти двое хороши как дополнение.
