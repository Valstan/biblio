# Переключатель VPN Happ — два ярлыка: вкл / выкл

Утилиты владельца для PC79: **переключатель VPN Happ** с двумя ярлыками на рабочем столе
(«VPN — включить (Happ)» и «VPN — выключить (Happ)»).

Заказ владельца 17.11 (про другой компьютер, где такое уже было): «VPN HAPP, созданы два
ярлыка, запуск и остановка ВПН, при этом маршруты для растдеск проложены при включенном впн
и наоборот прокси сделан при выключном впн для минидеска».

## Что внутри

| Файл | Что делает |
|---|---|
| `vpn-on.ps1` | **VPN — включить**: поднять Happ → прокси `10809` → системный прокси Windows → маршрут RustDesk → переменные прокси на Happ → перезапуск «МиниГена» → проба MiniMax |
| `vpn-off.ps1` | **VPN — выключить**: поднять резервный туннель → снять маршрут → погасить Happ → системный прокси выключить → переменные прокси на резерв `11081` → перезапуск «МиниГена» → проба; **если MiniMax не отвечает — откат, Happ возвращается** |
| `vpn-lib.ps1` | общие куски: проба API, переменные прокси, системный прокси, маршрут RustDesk, перезапуск контура «МиниГен» |
| `install-vpn-shortcuts.ps1` | создаёт два ярлыка на рабочем столе |

Живут на машине в `C:\Users\valstan\vpn\`; копия здесь — в git.

## Установка

```powershell
# 1. положить файлы в C:\Users\valstan\vpn\
# 2. создать ярлыки
powershell -ExecutionPolicy Bypass -File C:\Users\valstan\vpn\install-vpn-shortcuts.ps1
```

## Что происходит при переключении

**Включить:**

1. Поднимается Happ (служба `HappService` + окно), ждём прокси `127.0.0.1:10809`.
2. Включается системный прокси Windows → `127.0.0.1:10809`.
3. **Прокладывается маршрут для RustDesk**: `92.51.22.114` → `192.168.1.1`
   (`route -p add 92.51.22.114 mask 255.255.255.255 192.168.1.1 metric 1`) —
   чтобы RustDesk шёл мимо туннеля: иначе P2P не собирается и сессии рвутся.
4. Переменные прокси (`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`) → Happ.
5. **Перезапускается контур «МиниГен»** — старый процесс новых переменных не наследует.
6. Проба MiniMax через прокси: любой HTTP-ответ (даже 400) = путь живой.

**Выключить:**

1. Поднимается **свой резервный туннель** (`11080/11081`) — он теперь прокси для MiniMax.
2. Снимается маршрут RustDesk.
3. Гасится Happ (окно + служба): `10809` закрывается, маршрут по умолчанию туннеля исчезает.
4. Системный прокси Windows выключается.
5. Переменные прокси → резервный туннель (`11081`).
6. Перезапуск «МиниГена», проба MiniMax.
7. **Если MiniMax не отвечает — ОТКАТ: Happ возвращается** (маршрут и прокси обратно).

Оба скрипта **сами поднимают права администратора** (UAC): маршрут и службу иначе не тронуть.

## Порты и адреса (PC79)

| Что | Значение |
|---|---|
| Happ: socks / http | `127.0.0.1:10808` / `127.0.0.1:10809` |
| Резервный туннель (свой xray, `xtunnel.exe`) | `127.0.0.1:11080` / `127.0.0.1:11081` |
| RustDesk: ID- и relay-сервер | `92.51.22.114` (`rendezvous_server`) |
| LAN-шлюз | `192.168.1.1` |
| Журнал переключений | `C:\Users\valstan\vpn\vpn-switch.log` |

## Грабли (17.11)

- **Логгер в PowerShell нельзя писать через `Write-Output`** — вывод попадает в конвейер,
  возвращаемое значение функции становится массивом, и проверки `-not (Функция)` врут
  (ошибка маршрута не попадала в счётчик). Внутри — `[Console]::WriteLine`.
- **Проверка маршрута — по строке `route print <ip>`**, а не «есть IP в дампе таблицы»:
  иначе всегда «уже проложен».
- **Скрипты с кириллицей — UTF-8 с BOM**, иначе PowerShell 5.1 ломает парсер.
- Ядро резервного туннеля обновлять не нужно: `26.3.27` работает — сбой, который мы застали,
  оказался временным (серверный xray в этот момент перезапускался), а не из-за версии.
