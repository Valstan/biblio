# Архив: старая веб-панель «МиниГена»

**Что здесь.** Панель наблюдения `127.0.0.1:8099` и страница управления
`127.0.0.1:8098` вместе с её супервизором. До 23.11.2026 это был весь
интерфейс «МиниГена»: браузер + набор скриптов.

**Почему в архиве.** Заказ владельца (23.11): «переписать на графический
интерфейс… собрать в одну кучу, сделать одну единую программу». Новая
программа — `tools/minigen-gui/` — покрывает функцию панели:

| Что было в панели | Где теперь |
|---|---|
| список областей, вход, очки | вкладка «Области» |
| переключатель «Автомат/Вручную» | «Области» → «Режим» |
| «Запустить/Остановить десктоп» | «Области» → кнопки |
| «Новый вход (токен)» | «Области» → «Новый вход» |
| страница управления демонами (8098) | «Настройки» → «Демоны» |
| журнал сторожей | вкладка «Журнал» |
| проверка сети и вендора | вкладка «Сеть» |
| встроенная нейросеть | вкладка «Чат» |

**Что с демонами.** Супервизор держал не только панель, но и трёх демонов
(лечащий, сетевой сторож, сторож сессий). Теперь их держит сама программа
«МиниГен» (мост в режиме `--daemon`, автозапуск при входе в Windows).

**Файлы оставлены, а не удалены** — по канону репозитория (музей кода) и
на случай отката. Приёмочная проверка панели (`check_panel.py`) продолжает
работать: она берёт код отсюда и проверяет, что он разбирается.

**Не запускать.** Если эти файлы снова окажутся в `C:\Users\valstan\bin` и
запустятся, на машине появится вторая панель и, что хуже, **второй
процесс-менеджер демонов** — демоны начнут дублироваться (урок 22.11: две
копии лечащего брали аккаунты у КАРМАНА дважды). Проверка перед запуском:

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*minimax-autheal.py' } |
  ForEach-Object { $_.ProcessId }
```

Демон должен быть **один**. Если их два — второй лишний.
