# Установка «МиниГена» на новый компьютер

**Коротко:** программа ставится из репозитория одним скриптом. Вручную ничего
копировать не надо, в GitHub ничего заводить не надо.

## 1. Что нужно на машине

| Что | Версия | Зачем | Проверка |
|---|---|---|---|
| Windows | 10/11 x64 | окно программы | — |
| Node.js | 18+ | сборка окна | `node --version` |
| Python | 3.10+ | мост: команды, демоны, чат | `python --version` |
| Git | свежий | репозиторий | `git --version` |
| GitHub CLI (`gh`) | свежий | правки через PR и репозиторий своей копии | `gh --version` |

Вход в GitHub нужен **один раз на этой машине**:

```powershell
gh auth login
```

Без него программа не сможет открывать PR и завести репозиторий своей копии.

## 2. Откуда взять

Репозиторий программы — `Valstan/biblio`, ветка `master` (эталон версии).

```powershell
git clone https://github.com/Valstan/biblio.git D:\valstan\REPO\biblio
```

Путь может быть любым — программа запомнит его сама (настройка `codeRepo`).

## 3. Установка

```powershell
cd D:\valstan\REPO\biblio\tools\minigen-gui
powershell -ExecutionPolicy Bypass -File install.ps1
```

Установщик:

1. проверяет Node.js и Python;
2. ставит зависимости и собирает окно (`npm install`, `npm run build`) — долго,
   только при первом запуске;
3. ставит программу в своё место: `%LOCALAPPDATA%\Programs\МиниГен`;
4. делает ярлык **«МиниГен»** на рабочем столе и ярлык автозапуска
   **«МиниГен (демоны)»**;
5. записывает в `%LOCALAPPDATA%\minigen-gui\settings.json` путь к исходникам
   (`codeRepo`) — по нему программа потом обновляется сама (вкладка
   «Обновление»).

Повторный запуск `install.ps1` — это обновление: установщик идемпотентен.

## 4. Проверка

1. Ярлык «МиниГен» на рабочем столе → окно открылось.
2. Вкладка «Обновление» → «Проверить обновления» → «программа актуальна».
3. Вкладка «Сеть» → живых демонов **3/3** (лечащий, сетевой сторож, сторож
   сессий). Демоны поднимаются сами при входе в Windows (ярлык «МиниГен
   (демоны)»); вручную — `python "%LOCALAPPDATA%\Programs\МиниГен\app\bridge\minigen_bridge.py" --daemon`.

## 5. Это — новая копия (обмен генами)

Каждая установка на своей машине — **своя копия**: при первом запуске программа
заводит себе идентификатор (`mg-…`) и родословную (видно в `version.json`).

Свой репозиторий копии и клон пула наработок **заводит сама программа** —
вручную в GitHub ничего создавать не надо:

- вкладка «Управляющий» → инструмент `clone.setup` → программа создаст
  репозиторий `minigen-<идентификатор>`, возьмёт клон рядом с собой и
  подключит `upstream` (репозиторий программы) и клон пула генов.

⚠️ Действие опасное — создаёт репозитории в аккаунте владельца, поэтому
программа спрашивает подтверждение.

## 6. Почему вторая копия — это второй компьютер

Программа занимает **эксклюзивный порт API** (`:8097`, значение зашито в код) и
фиксированные каталоги (`%LOCALAPPDATA%\Programs\МиниГен`,
`%LOCALAPPDATA%\minigen-gui`). Два экземпляра на одной машине столкнутся: один
займёт порт, второй — каталоги, а демоны получат двух надзирателей (это уже
было: «демоны поднялись дважды за две минуты»).

⇒ Вторая копия = **отдельная машина** (или виртуалка со своей Windows).

Не путать с **областями**: области (`mcode-project-start.ps1 -Project <slug>`) —
это несколько *сессий агента* на одной машине (так устроены три экземпляра
Матрицы РМЗ). Копия программы — другое: у неё своя родословная, свой
репозиторий и участие в обмене генами.

## 7. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| окно не открылось | `cd tools\minigen-gui; npm run build` — посмотреть ошибку сборки |
| «Node.js не найден» | поставить Node.js 18+ и повторить `install.ps1` |
| «Python не найден» | поставить Python 3.10+ и повторить `install.ps1` |
| демонов меньше трёх | закрыть окно, запустить `install.ps1` заново (он поднимает фоновый режим) |
| программа старше, чем в репозитории | вкладка «Обновление» → «Обновить программу» → «Перезапустить программу» |
