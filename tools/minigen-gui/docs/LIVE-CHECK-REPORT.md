## Часть 2. Найденный живой пробой дефект протокола (и починка)

### 2.1 Как нашли

Живая история чата владельца лежит на диске машины:
`%LOCALAPPDATA%\minigen-gui\chat-history.json` (11 сообщений: 3 реплики владельца,
7 ответов, 1 системное). Последний ход **25.11 23:03:40** упал:

```
вендор ответил 400: invalid params, tool call result does not follow tool call (2013)
```

То есть вендор отверг ход: модель вызвала инструменты, а ответ вендор получил не на
все вызовы.

### 2.2 Живые пробы вендора (26.11)

Каждая проба — настоящий запрос к живой модели области (расход очков минимальный).

| Проба | Ход | Ответ |
|---|---|---|
| V1 | обычный вопрос | **200** |
| V2 | один `tool_use` → один `tool_result` | **200** |
| V3 | **два `tool_use` → один `tool_result`** | **400** «tool call and result not match (2013)» |
| V4 | две реплики владельца подряд | **200** |
| V5 | две реплики владельца подряд (иной текст) | **200** |
| V6 | `tool_result` + текст в одной реплике | **200** |
| W8 | два `tool_use` → `tool_result` + текст вместо второго ответа | **400** «tool call result does not follow tool call (2013)» — **дословно как в живой истории** |

**Правило вендора:** на **каждый** `tool_use` модели должен прийти свой
`tool_result`; иначе ход отвергается (400 / 2013). Текст рядом с ответом — можно,
пропущенного ответа — нельзя.

### 2.3 Причина в коде

`bridge/minigen_agent.py`, ветка опасных вызовов в `_loop()`:

- модель могла вызвать **несколько** инструментов в одном ходу (например
  `code.read` + `code.branch`);
- если среди вызовов был опасный, агент **не выполнял ничего** и отдавал вопрос
  владельцу;
- `confirm()` отвечал вендору **одним** `tool_result` — только на опасный вызов;
- второй вызов оставался без ответа ⇒ вендор отвергал ход (400).

То же самое в живом ходе 25.11: модель вызвала два инструмента, подтверждение
дали на один — и ход умер.

### 2.4 Починка

Правило вендора зашито в агента:

1. **Безопасные вызовы хода выполняются сразу** — они и не требуют подтверждения.
2. **Ход модели уходит вендору только после подтверждения всех опасных** вызовов:
   ответ на безопасные уже есть, на опасные — появится после решения владельца.
3. **`confirm()` отвечает на каждый `tool_use`** хода — и на каждый ответ
   `tool_use_id` совпадает.
4. **Несколько опасных вызовов подтверждаются по одному** — владельцу показывается
   текущий (имя, аргументы, причина), а не первый попавшийся.
5. **Отмена отменяет все опасные вызовы хода** и модель не зовёт (как и раньше:
   действие не сделано, ход вендору не уходит).
6. **Порядок ответов — как порядок вызовов модели** (`_ordered_results`): вендор
   сверяет вызов с ответом.

Проверенная форма хода после починки (её вендор принимает — 200):

```
user(текст)
assistant(текст, tool_use(code.read), tool_use(code.branch))
user(tool_result(на code.read), tool_result(на code.branch))
user(«владелец подтвердил действие, продолжай.»)
```

### 2.5 Регресс закрыт тестом

`bridge/tests/test_agent_protocol.py` (новый файл, 6 тестов):

- на каждый вызов модели — свой ответ (порядок ответов = порядок вызовов);
- опасный вызван первым — ответ тоже первым;
- два опасных вызова — два подтверждения, в баннере виден **текущий**;
- отмена отменяет все опасные вызовы и не зовёт модель;
- владелец видит результат инструмента **целиком**, вендору уходит обрезанное;
- несериализуемый результат не роняет ход.

Прочие правила промта #129, закрытые в этом же PR:

- **подробности не выбрасываются** (п.6): `calls[].result` — полный результат
  инструмента; обрезка (`TOOL_RESULT_LIMIT = 24_000`) осталась только в контексте
  модели. Владелец открывает детали по требованию и видит всё;
- **аргументы опасного действия — в свёртке** (п.5): в окне вместо сырого JSON
  свёртка «Что именно выполняется»; сам JSON — по клику;
- **ожидающее подтверждение и занятость живут вне вкладки** (п.4): уход на другую
  вкладку окна больше не съедает вопрос «подтвердите действие»;
- **гонка при восстановлении истории** устранена: пока переписка восстанавливается,
  отправка заблокирована — иначе ответ моста затирал бы уже отправленную реплику.

## Честные границы

- Отчёт фиксирует **факт наличия** нейросети и **работоспособность** цепочки
  `code.*`, а не качество любой правки: решение о слиянии PR #161 остаётся за
  владельцем.
- Живые пробы тратили очки области `minigen` (минимально: несколько коротких
  ходов). Токен наружу не печатался и в репозиторий не попадал (D-038).
- Черновые пробы лежат во временном каталоге машины и в репозиторий **не** попали.
- Отчёт не содержит секретов, полных путей машины и содержимого истории владельца
  целиком — только то, что нужно для приёмки.
