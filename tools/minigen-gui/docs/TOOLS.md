# Каталог инструментов «МиниГена»

Два каталога, один смысл:

- **команды программы** — то, что умеет окно (`bridge/minigen_bridge.py`);
- **инструменты нейросети** — обёртки над этими командами
  (`bridge/minigen_tools.py`). Каждый инструмент умеет ровно то же, что
  соответствующая кнопка в окне, и ничего больше.

Правило: **нейросеть не может сделать то, чего не может сделать владелец
через интерфейс**. Новый инструмент = новая кнопка.

## Опасность

| Пометка | Что значит | Как выполняется |
|---|---|---|
| безопасный | только читает | сразу |
| опасный | меняет состояние области или тратит очки | **только после подтверждения владельца** в чате |

Опасные инструменты: `areas.set_autoheal`, `areas.start`, `areas.stop`,
`areas.restart`, `areas.relogin`, `areas.create`, `sessions.send`,
`sessions.rotate`, `sessions.close`.

## Наблюдение

### `areas.list` — список областей
Команда `areas.list`. Поля: `slug`, `title`, `folder`, `karman`, `autoheal`,
`running`, `account` (вход по локальным файлам), `sessions` (вердикты),
`points` (если обновлялись). Побочных эффектов нет.

### `areas.state` — подробно про одну область
Команда `areas.state {slug}`. Плюс к списку — `diagnosis` (разбор лечащего:
«ОТКАЗ ПО ОЧКАМ», «ПОТЕРЯН ВХОД», «жива»). Побочных эффектов нет.

### `sessions.list` — сессии области с вердиктами
Команда `sessions.list {slug}`. Побочных эффектов нет.

### `sessions.read` — последние ходы сессии
Команда `sessions.read {slug, session_id}`. Побочных эффектов нет.

### `journal.read` — хвост журнала
Команда `journal.read {limit, contains, tag}`. Побочных эффектов нет.

### `reports.recent` — ящик отчётов
Команда `reports.list {limit, level}`. Отчёты сторожей и инструментов: что
сделали и где ошиблись (`level`: `info` / `warn` / `error`). Короче журнала
и с уровнем. Побочных эффектов нет.

### `stats.summary` — сводка работы
Команда `stats.summary {days}`. Считается по журналу: события по причинам,
по областям, по видам. Побочных эффектов нет.

### `network.check` — живая проба связи
Команда `network.check`. Проверяет пути (прокси) и вендора. **Идёт в сеть,
занимает секунды** — не звать без нужды. Побочных эффектов нет.

## Действия (требуют подтверждения)

### `areas.set_autoheal` — режим обслуживания
Команда `areas.set_autoheal {slug, autoheal}`. Пишет поле `autoheal` в
`mcode-project-areas.json` (атомарно). Лечащий перечитывает конфиг на
каждом проходе ⇒ действует без перезапуска.

### `areas.start` — запустить десктоп
Команда `areas.start {slug}`. Вызывает `mcode-project-start.ps1`, затем
**проверяет**, что процесс поднялся. Побочные эффекты: открывается окно
десктопа.

### `areas.stop` — остановить десктоп
Команда `areas.stop {slug}`. `mcode-project-stop.ps1`, затем проверка, что
процесс **ушёл**; если нет — добивание дерева процессов. Побочные эффекты:
работа в области прерывается.

### `areas.restart` — перезапуск десктопа
Команда `areas.restart {slug}`. Стоп с проверкой → пауза → старт → проверка,
что окно поднялось. Побочные эффекты: как у stop и start.

### `areas.relogin` — оживить вход
Команда `areas.relogin {slug}`. Берёт у КАРМАНА следующий аккаунт, сажает
его, перезапускает область. Побочные эффекты: **тратится аккаунт пула**.

### `areas.create` — новая область
Команда `areas.create {slug, title, folder, karman}`. Создаёт каталог данных,
копирует авторизацию из шаблона, пишет запись в конфиг. Побочные эффекты:
файлы и запись в конфиге.

### `sessions.send` — сообщение в сессию
Команда `sessions.send {slug, session_id, text}`. Побочные эффекты:
**тратятся очки** аккаунта области.

### `sessions.rotate` — ротация сессии
Команда `sessions.rotate {slug, session_id}`. Корректно закрыть → архивировать
→ открыть новую с той же работой. Побочные эффекты: старая нитка закрыта.

### `sessions.close` — закрыть сессию
Команда `sessions.close {slug, session_id}`. Побочные эффекты: работа нитки
прервана.

## Самообновление программы (нейросеть правит модули сама)

Заказ владельца: нейросеть «понимала работу программы, анализировала и могла
сама переписывать свои модули. Находила баги, нестыковки, расширяла
функционал».

Механика — `bridge/minigen_code.py`. Границы, которые здесь принципиальны:

- **правка идёт в отдельном git-worktree** (`.claude/worktrees/<имя>`), а не в
  дерево, где работает сессия: один писатель на область, «МиниГен» уже
  занят сессией;
- **только ветка и только PR.** Прямой пуш в `master` запрещён, решение о
  слиянии — за владельцем;
- **секреты не читаются**: файлы с ключами и авторизацией закрыты
  (`config.yaml`, `.env*`, `auth.json`, `*.pem`, `*.key`, имена с
  `token`/`secret`/`password`);
- **правка точная**: замена применяется, только если фрагмент встретился
  ровно один раз;
- **проверки обязательны**: `code.tests` гоняет проверки репозитория в том
  же worktree.

### Инструменты

| Инструмент | Что делает | Опасность |
|---|---|---|
| `code.list` | список файлов репозитория программы | безопасно |
| `code.read` | прочитать файл (большие — кусками: `start_line`/`end_line`) | безопасно |
| `code.search` | поиск по репозиторию: файл, строка, текст | безопасно |
| `code.branch` | создать worktree и ветку `agent/minigen-fix-<slug>` под правку | **опасно** (создаёт ветку) |
| `code.patch` | точная замена фрагмента в файле worktree | **опасно** (меняет код) |
| `code.tests` | прогнать проверки репозитория в worktree | безопасно |
| `code.commit` | закоммитить правку в ветку | **опасно** |
| `code.pr` | отправить ветку и открыть PR в `master` | **опасно** |
| `code.discard` | убрать worktree и его ветку | **опасно** |

Порядок работы: `code.search` → `code.read` → `code.branch` → `code.patch` →
`code.tests` → `code.commit` → `code.pr`. Каждый опасный шаг — с подтверждением
владельца.

## Чего в каталоге нет (и почему)

| Нет | Почему |
|---|---|
| `rollout.apply` | Раскатка на боевое место — **только по слову владельца**, отдельным действием, не из чата. |
| Правок ядра (`minimax-*.py`) | Ядро боевые и несут выученные уроки; их правка — по отдельному решению, не «по находке нейросети». |
| Инструментов для чужих областей и репозиториев | Правило владельца: чужие проекты не трогать. |


## Правила вызова

1. Сначала наблюдение, потом действие.
2. Опасное — с подтверждением; сомнение — спросить, а не угадывать.
3. Один писатель на область: если в области живая сессия — не начинать вторую.
4. Готовую работу не продолжать.
5. Отказ по очкам (`50110`) лечит лечащий — нейросеть не берёт новый аккаунт
   сама, если только владелец не попросил явно.
