# Проба самоотладки «Управляющего» — отчёт (25.11, промт #129)

**Заказ владельца:** «Проверить и описать, может ли Управляющий сам отлаживать
программу: цепочка `code.search → code.read → code.branch → code.patch →
code.tests → code.commit → code.pr` должна отработать на живой задаче «найди
дефект и почини» с открытым PR и зелёными проверками».

**Итог: цепочка отработала.** Управляющий нашёл настоящий дефект, починил его и
открыл **PR #161** с зелёными проверками. По дороге проба вскрыла ещё один
дефект — про бюджет задачи — его починили, и вторая проба прошла.

## Как устроена проба

- **мост берётся из установленной программы** (`%LOCALAPPDATA%\Programs\МиниГен\app\bridge`)
  — это тот же «Управляющий», что стоит у владельца на машине, с живым аккаунтом
  области `minigen`, с живым GitHub и с живым клоном копии;
- надзор демонов и раздача промтов в пробе **отключены** — проба не трогает
  боевых демонов и не отдаёт промты рабочим областям;
- опасные действия (`code.branch`, `code.patch`, `code.commit`, `code.pr`)
  подтверждаются автоматически: решение владельца на пробный ход зафиксировано
  в промте;
- весь диалог пишется в лог (файл лога — временный, в репозиторий не попал).

Задание, которое давалось Управляющему (дословно):

> Задача для пробы самоотладки: найди в исходниках программы «МиниГен»
> настоящий дефект и почини его своим ходом. Иди по цепочке: поиском
> (`code.search`), чтением (`code.read`), отдельной веткой и правкой
> (`code.branch`, потом `code.patch`), проверками (`code.tests`), коммитом и PR
> (`code.commit`, потом `code.pr`). Правка должна быть маленькой и проверяемой:
> сначала воспроизведи дефект, потом почини, потом покажи зелёные проверки. Не
> трогай мост и окно (`tools/minigen-gui/bridge/minigen_bridge.py`,
> `tools/minigen-gui/bridge/minigen_agent.py`, `tools/minigen-gui/src/renderer`)
> — там сейчас идут правки, выбери дефект в другом месте. В конце ответь
> коротко: что нашёл, что починил, ссылка на PR.

Ограничение по файлам — **не** часть заказа, а практическая necessity пробы:
в этот момент в мосте и окне шли правки промта #129, и дефект там был бы
неразличим с нашими.

## Проба №1 — не прошла, и это оказалось важнее

| | |
|---|---|
| время | 25.11, 14:53–14:57 (215 с) |
| исход | «достигнут лимит шагов (24) — сузьте запрос» |
| что сделал Управляющий | совет специалистов → `code.list`, `code.search`, `code.read` (×4), `state.snapshot`, `program.version`, `code.tests` |
| чего не хватило | `code.branch` / `code.patch` / `code.commit` / `code.pr` — до них ход не дошёл |

**Причина — дефект, а не «модель не справилась».** Бюджет задачи был **общим**:
совет специалистов (заказ владельца, промт #132) забирал его целиком, и на
саму работу оставалось **4 шага**. А задача «найди дефект и почини» по
инструкции самой программы требует ~10 вызовов
(`docs/knowledge-pack.md` → «Если просят починить саму программу»).

**Починка** (`bridge/minigen_agent.py`): бюджет задачи **один** и делится между
советом и работой. Совет занимает не больше своей доли (`councilRounds`, дефолт
12 раундов из 24), работа получает остаток, но не меньше гарантированного
запаса (`councilWorkFloor`, дефолт 12). Совет обсуждает — работа делает; одно
не отменяет другого, и раундов на задачу не больше `MAX_ROUNDS = 24`. Проверено
тестом (`bridge/tests/test_council.py` → «совет занимает часть бюджета, работа —
не меньше запаса»).

⚠️ Честно о цене: раньше (25.11) бюджеты были раздельные — совет до 16, работа
все 24, итого до 40 вызовов модели на задачу. Теперь верхняя граница одна:
24. Числа взяты из живых проб 26.11: работа по задаче «объясни, как устроен
совет» без совета занимает 12 раундов, а полный совет — не меньше 14, то есть
на 24 раундах обе части не помещаются. Владелец может урезать расход ещё
сильнее, уменьшив число ролей (`councilMaxRoles`) или выключив совет в
настройках.

⚠️ С 26.11 деление бюджета — **настройка владельца**, а не число в коде
(Настройки → «Совет специалистов»): `councilRounds` и `councilWorkFloor`.
Дефолты те же (12 и 12). Если числа не влезают в общий бюджет задачи — уступает
совет: запас работы гарантирован, а не выбирается.

## Проба №2 — прошла

| | |
|---|---|
| время | 25.11, 15:07–15:21 (852 с, 13 ходов) |
| исход | «Готово» + ссылка на PR |
| PR | **https://github.com/Valstan/biblio/pull/161** (ветка `agent/minigen-fix-demon-opoznavanie-po-kontsu-komandnoi-st`) |
| проверки PR | `gate` — **SUCCESS** (зелёные) |
| состояние | PR открыт, `MERGEABLE`; **решение о слиянии — за владельцем** |

### Цепочка, которая отработала

| Шаг | Инструмент | Что было |
|---|---|---|
| 1 | `code.search`, `code.read` | поиск дефекта: `tools/minigen-gui/bridge/minigen_daemons.py`, функция `daemon_pids()` |
| 2 | `code.branch` | отдельная ветка и worktree |
| 3 | `code.patch` | падающий тест `test_daemon_pids_skips_one_shot_calls` — `[4242, 5150] != [4242]` (красные) |
| 4 | `code.tests` | после правки — 304 теста моста зелёные; `all` — мост, приёмка панели, приёмка записи конфига зелёные |
| 5 | `code.diff` | проверка diff перед коммитом |
| 6 | `code.commit` | коммит в ветку |
| 7 | `code.pr` | **PR #161** открыт |

### Что за дефект нашёл Управляющий

Докстринг `daemon_pids()` обещает: «условие — командная строка **ЗАКАНЧИВАЕТСЯ**
именем скрипта», но запрос WMI отбирал процессы по шаблону «командная строка
**СОДЕРЖИТ** имя скрипта» (`-like '*minimax-sessionwatch.py'`). Разовый вызов
(`minimax-sessionwatch.py --list`, `--send`, `--new`) считался живым демоном.

Последствия (живые): окно и API показывают «демоны 3/3», когда демоны мертвы;
`start()` отвечает «уже работает» и не поднимает ничего ⇒ демон молчит (лечащий
не чинит аккаунты, сторож сессий не ждёт сессии); `stop()` может убить чужой
разовый вызов. Прежний тест это не ловил — он составлял шаблон **в самом тесте**
и проверял его, а не код программы.

Правка: запрос WMI отдаёт «pid <TAB> командная строка», отбор перенесён в
Python — новая чистая функция `is_daemon_command()` (имя скрипта **в конце**
строки). Затронуты два файла: `minigen_daemons.py` и `bridge/tests/test_daemons.py`.

## Честные границы пробы

- **Проба шла с автоматическим подтверждением** опасных действий. В обычной
  работе владелец подтверждает их сам — так и задумано (правило программы).
- **Совет специалистов в пробе участвовал** и стоил части шагов: два голоса
  «не уложились в 2 шага» — их предел мал, но на решение совета это не
  повлияло.
- Проба проверяла **возможность** Управляющего чинить программу (и делать это
  через ветку и PR), а не качество любой правки: решение о слиянии PR #161 —
  за владельцем, как и за любой другой правкой.
- Отчёт пишет **источник и результат**, но не содержимое секретов и полных
  путей машины (D-038).
