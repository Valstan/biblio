## 1. Что должно получиться

Одна программа «МиниГен» — окно Windows, без браузера и без набора разрозненных скриптов, которыми надо управлять вручную. Внутри окна:

1. **Вкладка «Области»** — все рабочие области (сейчас их 19): состояние десктопа, вход, очки, заполнение контекста, последнее действие сторожей; кнопки «запустить десктоп», «остановить», «оживить вход», «открыть папку»; **создание новой области** из окна.
2. **Вкладка «Статистика»** — общая статистика работы: перезапуски областей (и по каким причинам: отказ по очкам `50110`, компактизация контекста, обрыв сети, ручной перезапуск), сколько раз перезапускались, когда последний раз, uptime; экспорт в CSV.
3. **Вкладка «Сеть»** — проверка «видят ли рабочие области интернет» (и вендора MiniMax): по каждой запущенной области — доступность вендора, путь (прокси/VPN), устойчивость связи; кнопка «проверить все».
4. **Вкладка «Чат»** — встроенная нейросеть (MiniMax) с инструментами: отвечает на запросы владельца и **выполняет** их; видит состояние программы, сама выбирает, что делать; при недоступности нейросети управление автоматически уходит алгоритмическим функциям (сторожам).
5. **Вкладка «Журнал»** — единый журнал (сторожей + решения нейросети), с фильтрами.
6. **Вкладка «Настройки»** — автолечение вкл/выкл, интервалы сторожей, пути.

Плюс обязательный результат: **встроенная нейросеть умеет переписывать модули самой программы** — находить баги и нестыковки, расширять функционал, править код и обновлять программу.

## 3. Границы решения (заданы Управляющим 23.11.2026 — не переигрывать молча)

1. **Стек GUI: Electron + TypeScript + React.** Тот же стек, что у «Матрицы РМЗ» — владелец его знает; electron уже скачан в `node_modules` на этой машине (переиспользовать, не качать заново). Альтернатива, если electron- сборка на парке упрётся: WinForms/PowerShell (как `net-monitor`). Выбор зафиксировать ADR-ом в этом же репозитории.
2. **Логика сторожей не переписывается в TypeScript.** Демоны — боевые и несут выученные уроки (грабли `G678`–`G681`, `M42`-подобные). Python-ядро остаётся ядром; GUI — оболочка и оркестратор.
3. **Одна программа, один процесс-менеджер:** Electron-приложение само поднимает и следит за Python-демонами, а не «просит владельца запустить их руками».
4. **Старую панель `:8099` и страницу `:8098` не выключать**, пока новая программа не покрывает их функцию; в Ф6 — переключение и архив.
5. **Секреты, токены, ключи — только из окружения/конфигов, никогда в git.**
6. **Раскатка на боевое место (`C:\Users\valstan\bin`) — только по слову владельца.** До этого — локальный прогон/`--dry-run`.

```
┌─────────────────────────────────────────────────────────────┐
│ Слой 4 — встроенная нейросеть (MiniMax)                     │
│ агент-цикл: мысль → вызов инструмента → наблюдение → вывод  │
│ системный промпт = docs/knowledge-pack.md (устройство        │
│ программы) + каталог инструментов + правила безопасности    │
└───────────────┬─────────────────────────────────────────────┘
                │ tools (JSON)
┌───────────────▼─────────────────────────────────────────────┐
│ Слой 3 — Electron: renderer (React) + main (IPC, процессы)  │
│ вкладки: Области · Статистика · Сеть · Чат · Журнал · Настройки │
└───────────────┬─────────────────────────────────────────────┘
                │ локальный IPC (stdio/TCP 127.0.0.1 + токен)
┌───────────────▼─────────────────────────────────────────────┐
│ Слой 2 — мост: Python-сервис поверх minigen_core.py         │
│ один JSON-lines канал: команды → демоны, события → GUI      │
└───────────────┬─────────────────────────────────────────────┘
                │ импорт/запуск
┌───────────────▼─────────────────────────────────────────────┐
│ Слой 1 — ядро (Python, боевой код): лечащий, сетевой        │
│ сторож, сторож сессий, общие утилиты, чтение состояния      │
└─────────────────────────────────────────────────────────────┘
```

Принцип: **у каждого слоя одна ответственность, логика не дублируется**. То, что уже умеет Python-ядро, GUI не переписывает — GUI спрашивает и показывает.

## 5. Фазы

Каждая фаза — отдельный PR (ветка от `master`), зелёный гейт, merge. Ничего не раскатывается на машину без слова владельца.

### Ф0 — каркас и среда
- `tools/minigen-gui/`: каркас Electron + TypeScript + React; окно с закладками-заглушками; сборка; `install.ps1` + `Запустить.cmd` по образцу `tools/README.md`; ярлык на рабочем столе «МиниГен».
- ADR: выбор стека (Electron vs WinForms) с обоснованием.
- Мост: Python-сервис, который поднимается приложением и отвечает по JSON-lines на «список областей» (read-only) — проверка, что канал работает.
- **Приёмка:** запускается одним ярлыком, окно Windows, вкладки на месте, вкладка «Области» показывает реальные 19 областей из конфига.

### Ф1 — единый источник состояния
- Собрать состояние из разрозненных источников в одну структуру: области (конфиг), десктопы (процессы), вход/очки, сессии (база рантайма), сеть, журнал.
- Один модуль-агрегатор в Python (`minigen_core.py` + новый модуль), доступный и GUI, и нейросети.
- **Приёмка:** одно и то же состояние показывается в GUI и возвращается тем же кодом в чат.

### Ф2 — управление областями
- Старт/стоп десктопа области, оживление входа (device-flow), **создание новой области** (папка + каталог данных + копия авторизации + запись в `mcode-project-areas.json` + ярлык + рабочая папка/ветка).
- Управление сессиями: открыть/закрыть/ротация/«Продолжай» — через существующие функции сторожа сессий.
- **Приёмка:** из окна создаётся новая область, которая запускается и видит интернет; действия видны в журнале.

### Ф3 — статистика и сеть
- Счётчики: перезапуски (с причиной), отказы по очкам, обрывы сети, uptime, заполнение контекста; история с разбивкой по областям; экспорт CSV.
- Проверка «видят ли области интернет»: проба вендора из контекста области, проверка пути (прокси/VPN), устойчивость связи (несколько попыток), «проверить все».
- **Приёмка:** видно, кто и когда перезапускался и почему; по каждой запущенной области — зелёный/красный статус сети.

### Ф4 — чат и встроенная нейросеть
- Окно чата: сообщения, поток ответа, **видимые вызовы инструментов** (что нейросеть сделала), подтверждение опасных действий.
- Агент-цикл: модель MiniMax (из `config.yaml` провайдера), системный промпт = сведения об устройстве программы + каталог инструментов + правила.
- Инструменты первого эшелона: `areas.list`, `areas.start`, `areas.stop`, `areas.create`, `areas.relogin`, `sessions.list`, `sessions.read`, `sessions.send`, `sessions.close`, `sessions.rotate`, `network.check`, `journal.read`, `stats.summary`.
- **Фолбэк:** если модель недоступна (отказ по очкам `50110`, обрыв сети, нет ключа) — чат честно сообщает, что нейросеть недоступна, и **управление остаётся у алгоритмических функций** (сторожей продолжают работать как сейчас, без вмешательства). Проверяется тестом «модель недоступна ⇒ демоны работают».
- **Приёмка:** в чате «проверь интернет у всех областей» — нейросеть вызывает инструменты и отвечает по фактам; при выключенной модели демоны продолжают свою работу.

### Ф5 — самообновление программы
- Инструменты работы с кодом: `code.read`, `code.search`, `code.patch`, `code.branch`, `code.commit`, `code.pr`, `code.tests`.
- Нейросеть может читать модули программы, находить баги/нестыковки, предлагать и вносить правки **в ветке** и открывать PR — по правилам репозитория (без прямого пуша в `master`).
- «Обновить программу на машину» — отдельное действие (раскатка `minigen_rollout.py`), с явным подтверждением владельца.
- **Приёмка:** нейросеть по запросу «найди, где теряется контекст при ротации» читает код, предлагает правку, оформляет ветку и PR.

### Ф6 — переключение
- Новая программа покрывает функции `:8099`/`:8098` → старые панели уходят в архив (файлы остаются в репозитории с пометкой), раскатка ставит новую программу.
- Обновление документации, `docs/SESSION_HANDOFF.md`, `tools/README.md`.
- **Приёмка:** владелец открывает одну программу вместо браузера + скриптов.

## 6. Каталог инструментов встроенной нейросети (проект, раскрывается по мере фаз)

|---|---|---|
| `areas.list` / `areas.state` | список областей, их состояние | безопасно |
| `sessions.list` / `sessions.read` | сессии области, последние ходы | безопасно |
| `journal.read` | журнал программы | безопасно |

| `sessions.send` | сообщение в сессию | может занять очки |
| `areas.start` / `areas.stop` | десктоп области | видимая действие, с подтверждением |
| `areas.relogin` | оживить вход (device-flow) | интерактив с владельцем |
| `areas.create` | создать область | создаёт файлы и записи в конфиге |
| `sessions.rotate` / `sessions.close` | ротация/закрытие сессии | может оборвать работу |
| `code.read` / `code.search` | чтение кода программы | безопасно |

Правило для агент-цикла: сначала **наблюдение** (`areas.list`, `journal.read`, `stats.summary`), потом **действие**; неоднозначные и разрушительные действия — с подтверждением; сомнение — спросить владельца, а не гадать.

## 8. Предохранители (обязательны, не обсуждаются)

1. **PR-only flow:** ветка → коммит → push → PR → зелёный гейт → merge в `master`. Прямой push в `master` запрещён.
2. **Никакой раскатки на боевую машину без слова владельца.** Живые файлы в `C:\Users\valstan\bin` — не трогать руками; эталон — репозиторий.
3. **Прод и чужие проекты не трогать.** Матрица РМЗ, Сарафан, Карман и прочие области — только наблюдать и чинить по правилам существующих сторожей.
4. **Один писатель на область.** Перед тем как писать в чужую область — проверка «место занято» (в области уже есть живая сессия → не начинать вторую).
5. **Секреты — не в git.** Ключ MiniMax читается из `config.yaml` области в рантайме.
6. **Ничего не ломать на живых десктопах «на пробу».** Новые команды сторожей сначала в dry-run, потом в бой.
7. **Публичный репозиторий:** в код/доки/письма не класть хостнеймы, IP, порты, имена хостеров, состав жильцов боксов (правило D-038 в `AGENTS.md`).
