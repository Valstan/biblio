## Сделано позже в тот же день: net-monitor (PR #7)

Утилита научилась отвечать на вопрос «Claude завис или отвалился интернет» и
восстанавливать связь. Ключевое из разведки: **обычные проверки здесь врут** — TUN
отвечает на ping сам (0 мс при мёртвом канале), а соединения Claude Code идут на
локальный прокси и живут при полном обрыве. Детали устройства канала — в
[дизайн-спеке](superpowers/specs/2026-08-26-net-monitor-autorecovery-design.md).

- Автовосстановление **выключено по умолчанию**, идёт по одному шагу за такт таймера
  (иначе трей замерзал бы на минуты), пороги 3/6 плохих тактов, пауза после неудач.
- Перезапуск VPN и адаптера — отдельные галки, требуют **подтверждения**, что страна
  выхода прежняя; «подтвердить не удалось» останавливает лестницу.
- Стоп-лист в коде: метрики в пользу физического адаптера, IPv6, сброс стека,
  перезапуск туннельного адаптера, правка конфигов клиента — никогда.
- Ревью нашло 14 дефектов, все исправлены (включая инвертированный ассерт, из-за
  которого главный сценарий не работал вовсе).

**Открыто у владельца:** включать ли автовосстановление и разрешать ли тяжёлые ступени;
что делать с отсутствующим killswitch (брандмауэр Windows выключен во всех профилях) и
с утечкой plain-DNS мимо туннеля — обе находки вне рамок задачи, не трогались.

## Сделано в тот же день: портируемость net-monitor (PR #9)

Заказ владельца — отправить утилиту другу. Выяснилось, что в прежнем виде отдавать её
было нельзя: на машине без VPN она **изобретала аварии** (вечный оранжевый значок
«туннель не поднят», а с автовосстановлением — бесконечная лестница за несуществующим
VPN). Тот же ложный диагноз получал пользователь WireGuard/OpenVPN.

- Ничего больше не предполагается: отсутствие VPN, Claude Code и незаданная страна —
  нормальные состояния. Распознаётся и штатный VPN Windows.
- **Дыра, которую эта же правка едва не создала:** признак «VPN тут настроен» выводился
  из живости клиента — значит его выключение гасило бы контроль страны и утечки ровно
  тогда, когда трафик пошёл с домашнего адреса. Факт «VPN здесь был» теперь запоминается.
  Инсайт вынесен письмом Мозгу.
- `build-package.ps1` собирает zip (~42 КБ), по умолчанию склеивая модули в один скрипт.
  Лаунчер снимает пометку «файл из интернета» и отказывается работать из папки
  предпросмотра архива. В архиве — `ДЛЯ-ПОЛУЧАТЕЛЯ.txt`.
- **Решено не паковать в .exe** — обоснование в README (антивирусные эвристики плюс
  потеря читаемости у инструмента, который просит администратора и правит DNS).

⚠️ **Для владельца:** контроль страны теперь по умолчанию выключен (иначе друг видел бы
«страна сменилась», просто живя дома). При первом запуске утилита один раз спросит,
следить ли за текущей страной — ответить «Да».

## Грабли сессии

- В одном рабочем дереве параллельно шла вторая сессия (ветка `kaspersky-matrica-tool`):
  её `git checkout` увёл дерево с чужой ветки, коммит едва не сел мимо PR-flow. При
  одновременной работе — отдельный `git worktree` каждому агенту (ADR-0011).
- **`.ps1` обязаны быть в UTF-8 с BOM**: утилиты запускаются через `powershell` 5.1,
  который без BOM читает файл как ANSI — кириллица ломается, и скрипт молча перестаёт
  работать (в `pwsh` 7 при этом всё выглядит исправным). `.cmd` — наоборот, ASCII без BOM.
- **Проверять надо тем же путём, которым ходит рабочий трафик.** Здесь ping к
  api.anthropic.com отвечает за 0 мс даже при мёртвом канале (за адресата отвечает
  TUN-драйвер), а соединения Claude Code всегда ведут на локальный прокси и переживают
  полный обрыв. Инсайт вынесен письмом Мозгу.
- **Признак «эта защита применима» нельзя выводить из состояния защищаемого объекта** —
  иначе предохранитель самоустраняется при аварии. Второе письмо Мозгу.
