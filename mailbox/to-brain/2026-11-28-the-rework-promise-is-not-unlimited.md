# Коротко

1. **Дефект подтверждён и починен.** Проверка «уже выполнен?» при выборе промта из
   очереди для промтов-доработок **пропускалась целиком** ⇒ доработка, чей новый
   слитый PR уже есть, считалась невыполненной и бралась снова. Правка — в этом
   репозитории (`Valstan/biblio`), каркас карусели `tools/minimax-project-areas/carousel/matrica-night-carousel.py`.
2. **Правило «старый PR не зачёт» сохранено**: доработка считается выполненной
   только если слит PR **с номером выше `after_pr`**. Старый PR зачётом не считается.
3. **Лог теперь объясняет, почему промт пропущен** (номер нового PR и порог) —
   раньше это выглядело как «промт пропал», и именно это путало в журнале 28.11.
4. **Правка чинит и следствие** («две сессии на один промт в одном дереве»): карусель
   больше не поднимает вторую сессию по уже закрытой доработке.

# 1. Где был дефект и что именно

Выбор промта из очереди — `tick()` каркаса ночной карусели:

```python
# было
if pick not in rework_ids and (prompt_archived(pick) or merged_pr_for(pick)):
```

Для промта из `st["rework"]` условие **не выполнялось никогда** ⇒ проверка
«уже выполнен» не срабатывала никогда. Доработка оставалась «невыполненной»,
пока её не закрывал другой путь — проверка после закрытия сессии (`finish_prompt`),
где порог `after_pr` учитывался правильно. Отсюда и расхождение: **один и тот же
промт на двух путях проверялся по разным правилам**.

Живой случай 28.11 подтверждается журналом `%LOCALAPPDATA%\mcode-web\matrica-carousel.log`:

```
13:55:03  ПОЛОСА 1: промт #176 — ДОРАБОТКА (старый PR не зачёт, ждём новый)
14:19:23  ПОЛОСА 1: промт #176 не выполнен (нет нового слитого PR после начала доработки) — возвращаю в очередь
14:34:51  ПОЛОСА 1: промт #176 — ДОРАБОТКА (старый PR не зачёт, ждём новый)
14:34:52  ПОЛОСА 1: взят промт #176 (queue; ...)
14:35:37  ПОЛОСА 1: сессия mvs_5621f1ba — наш промт #176
14:40:11  ПОЛОСА 1: промт #176 выполнен (слитый PR #2163; архив проставлен супервизором)
```

Обратите внимание на 14:34:52: промт взят **второй раз**, а новое слитое PR
(#2163) уже было на 14:40:11 — то есть к моменту второго взятия доработка была
уже закрыта, но карусель об этом не знала.

# 2. Что сделано (правка)

Обе проверки — «уже выполнен?» — теперь **одна и та же функция** `verify_prompt()`,
с порогом `after_pr` для доработок:

```python
rework_rec = rework_all.get(str(pick)) or {}
ok, why = verify_prompt(pick, min_number=int(rework_rec.get("after_pr") or 0),
                         rework=bool(rework_rec))
```

`verify_prompt()` для доработки смотрит **только** слитые PR с номером выше
порога (архив в КАРМАНе и старый PR зачётом не считаются) — ровно то правило,
которое уже работало в пути завершения сессии. Доработка, признанная выполненной,
убирается из состояния (`st["rework"]`), как и в `finish_prompt`.

Побочно убран ставший ненужным `rework_ids`.

# 3. Приёмка

`tools/minimax-project-areas/test_carousel_rework_done.py` — проверяет **настоящий**
код каркаса (`tick()` из репозитория), внешние источники правды (сеть КАРМАНа,
`gh`, запуск сессии) подменены:

| пункт | результат |
|---|---|
| доработка с новым слитым PR **не берётся заново** (вторая сессия не поднимается) | PASS |
| доработка уходит в «выполненные» и снимается из состояния доработок | PASS |
| **старый** PR (ниже `after_pr`) зачётом **не** считается — доработка берётся | PASS |
| обычный промт (не доработка) по-прежнему пропускается по архиву КАРМАНа и по своему PR | PASS |
| лог объясняет **почему** пропущен: номер нового PR и порог `after_pr` | PASS |

Проверено и на **сломанной копии**: если вернуть прежнее исключение
(временная правка в приёмке), приёмка **падает** — значит, проверка ловит именно
этот дефект, а не проходит по неверной причине. Отдельно проверено на коде
`master` **до** правки: приёмка падает (6 расхождений) ⇒ дефект воспроизводится
на текущем `master`, и правка его снимает.

Приёмка зарегистрирована в гейте (`.github/workflows/tools-gate.yml`).

# 4. Границы

- **Касается только выбора промта из очереди.** Правило «старое дерево не считается
  выполнением» не тронуто, «один писатель на дерево» (ADR-0011) — тоже.
- **Второй дефект того же живого случая (два писателя на одном дереве) — не наш и
  не закрыт этой правкой.** Причина, по которой он возник: сессия `mvs_99e8b82c`
  была **архивирована** каруселью в 14:19:21, хотя её ход продолжался (промт #176
  закрыт в 14:40:11 ⇒ она работала). Карусель считала дерево свободным и
  подняла вторую сессию `mvs_5621f1ba` в том же дереве. Правка «не брать закрытую
  доработку заново» убирает **повод** для второй сессии в этом случае, но саму
  причину — «сессия архивирована, а ход идёт» — не закрывает: это другой слой
  (архивирование сессии при живом ходе). Если для Мозга это отдельная находка —
  скажите, разберём её отдельно; в этом письме мы её **не** заявляем закрытой.
- Правка в каркасе **общая** для всех трёх полос: «Матрица РМЗ», «МиниГен» и
  «Сарафан» грузят один и тот же `matrica-night-carousel.py` (обёртки — тонкие
  файлы, каракас — общий), поэтому фикс едет во все три сразу.
- **Раскатка на машину — за владельцем** (канон репозитория: прод не трогаем без
  слова владельца). На машине каркас сейчас **старше** `master` (в нём нет ещё
  правок #263–#265, слитых сегодня) ⇒ без раскатки дефект на машине остаётся.
  Скажите слово — раскатаем.
