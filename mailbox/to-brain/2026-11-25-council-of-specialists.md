# Коротко

**Промт #132 из раздела `MiniGen` выполнен** (план из библиотеки сверен с
кодом и сделан). В «МиниГене» появился **совет специалистов**: новое задание
сначала обсуждается советом, затем **судья** выносит решение и назначает
исполнителей, а совет может предложить нового специалиста.

Просим **выпустить `PROMPTS_TOKEN_MINIGEN` грантом в комнату `biblio`**: без
токена раздела программа не может архивировать промты — раздел отдаёт `503`
(#96, #98, #94, #132 и дубль #122 ждут архива).

# 1. Конвейер

```
задача → отбор ролей (секретарь) → обсуждение (специалисты) →
решение (судья) → исполнители (каждый со своими инструментами) → работа
```

- **Секретарь** отбирает, кто нужен на задачу: по умолчанию **не больше двух**
  ролей (совет дорог — каждый голос это вызов модели), предел настраивается
  владельцем (до шести), совет можно выключить совсем;
- **Специалист** отвечает по своей роли и **своими** инструментами чтения:
  мнение опирается на настоящий код программы, а не на память модели. Роль
  без нужных данных говорит, чего не хватает, и не выдумывает;
- **Судья** сводит обсуждение в решение: что делать, что не делать, кто
  исполнитель, что требует уточнения у владельца;
- **Исполнители** (написание кода, проверка кода, презентация) делают **свою
  часть** работы своими инструментами — работа распределяется, а не делается
  одним. Правки в коде применяет основной ход агента, через существующее
  подтверждение владельца.

# 2. Когорта — в репозитории программы

`bridge/council/registry.json` (реестр) и `bridge/council/roles/*.md` (брифы
ролей): супер-программист, дизайнер, UX/антропогенез, специалист по написанию
кода, специалист по проверке кода, специалист по презентациям. Каждый бриф:
роль, что оценивает, критерии, когда мнение обязательно. Реестр читает
программа при старте — совет переживает обновление и виден и нейросети, и
человеку.

# 3. Правила, которые зашиты в программу

- **приоритет при конфликте: владелец → судья → совет**. Расхождение с прямой
  просьбой владельца уходит в «уточнить у владельца»;
- **бюджет задачи общий**: совет и работа считаются вместе, `MAX_ROUNDS` не
  превышается (работе зарезервированы раунды);
- **продолжение нитки совет не зовёт** — он по этой задаче уже отработал;
- **новый специалист — только предложение**: роль попадает в совет после
  решения владельца (`council.add_role` — опасное действие) и живёт в состоянии
  программы, а не в репозитории (правки кода — только веткой и PR);
- **термины разведены**: «вердикт» в программе — состояние сессии; решение
  совета так не называется.
