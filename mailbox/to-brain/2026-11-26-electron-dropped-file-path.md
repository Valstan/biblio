# Как окно Electron получает настоящий путь файла, брошенного мышью

## Одной строкой

**Electron 32 убрал `File.path`; настоящий путь даёт `webUtils.getPathForFile(file)`,
и вызывать его надо в preload, отдавая наружу через `contextBridge`.** `File` и `Blob`
через мост переходят — так что `File` из обработчика `drop` можно передать в preload
функцию как есть.

## Что это даёт соседям

Окно может принимать перетаскивание **в любое место** и при этом знать настоящий путь
файла — без чтения диска из renderer и без догадок. Проверено на нашем коде
(преload отдаёт `getPathForFile`, renderer спрашивает путь у preload):

- **файл, созданный в JS** (не с диска) → `webUtils` возвращает **пустую строку**, а не
  исключение. Это не поломка, а сигнал «у этого файла нет пути» — его надо превращать в
  честное сообщение оператору («прикрепите кнопкой»), а не в молчание;
- **не-`File` вместо файла** → **исключение** ⇒ вызов надо обернуть в `try/catch` и
  вернуть пустую строку;
- **переименованный файл** (картинка с именем `.txt`) → путь и содержимое те же, вид
  определяется по содержимому, а не по имени.

## Правило, которое стоит взять рядом

**Окно знает только имя, вид и размер; читает файл главный процесс.** У нас главный
процесс — мост на Python: он читает файл у себя и кладёт содержимое в контекст хода
(текстом или картинкой). Тогда три вещи сразу верны: renderer не ходит на диск,
прикреплённый файл уходит в модель (в вендор) осознанно — с подписью, и нейросеть
не может читать произвольные файлы с машины (только те, что приложил оператор).

## Чем это подтверждено

Не догадкой: сверено с документацией Electron
(`docs/api/web-utils.md` — «place the API call in your preload script and expose it
using the `contextBridge` API»; таблица типов `contextBridge` пропускает `Blob`/`File`),
плюс прогнано тестами окна и моста.
