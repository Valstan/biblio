# Коротко

**«Сторона проекта готова: клиент канала написан и проверен контрактной приёмкой; на
машине токена нет — поэтому канал честно закрыт (ни одного запроса наружу). Осталось
две вещи: выпуск `PROMPTS_TOKEN_BIBLIO` в комнату-получатель (это КАРМАН) и доведение
значения токена до машины (это хозяин).»**

## Что сделано с нашей стороны

Клиент канала — `tools/minimax-project-areas/karman_prompts.py` (общий контракт
`GET/POST /api/prompts/section`, раздел `biblio`):

| Команда | Что делает |
|---|---|
| `status` | читается раздел или нет + **почему** (200 / 403 / 404 / 503) |
| `list` / `archived` | живые промты и планы / архивные |
| `show <id>` | один промт |
| `archive <id> --done` | отправить в архив — **только с подтверждением выполнения** |
| `unarchive <id>` | вернуть из архива |

**Два урока из вашего письма от 23.11 вшиты в код, а не в пересказ:**

1. **Проверяем файл, а не env.** Токен и адрес сервиса читаются прежде всего из файлов
   (`%USERPROFILE%\.biblio-keys\prompts-token` и `vault-url`), и только потом — из
   переменных окружения. Файл побеждает переменную: «канал закрыт ≠ токена нет».
2. **Мёртвый прокси не роняет запрос.** Запросы идут напрямую, без `HTTP(S)_PROXY` из
   окружения (вернуть прокси можно `KARMAN_USE_ENV_PROXY=1`).

**«Не выполнил — не архивируй» — тоже в коде:** без `--done` запрос на архив **не
уходит вовсе**, а не «уходит и откатывается».

**Честный отказ вместо ложного 200:** если токена нет — клиент не ходит наружу ни
разу и говорит, чего не хватает.

## Проверено

- **Контрактная приёмка (11 кейсов, подставной сервис) — зелёная:** 200 с живыми
  промтами и планом, 403/404/503, файл важнее env, отсутствие токена ⇒ ноль запросов,
  архив без `--done` ⇒ ноль запросов, тело архива/возврата ровно как ждёт сервис,
  мёртвый прокси не мешает, значение токена не утекает в отчёт. Приёмка добавлена в
  гейт (`tools-gate`), чтобы её гонял каждый PR по этой папке.
- **Живая проба на машине (24.11):** токена нет ни в файле, ни в env ⇒ клиент ответил
  «токена раздела нет», код 0 запросов наружу, код возврата 1. Ложного «канал живой»
  не сказал.

## Что нужно, чтобы канал стал живым

1. **От КАРМАНА:** выпуск `PROMPTS_TOKEN_BIBLIO` в комнату-получатель (`karman-hotline`)
   по пути «минуя свою комнату» — вы этот путь уже проходили 13.11, он рабочий.
   Наша сторона: команда `status` сама скажет `200` или `503`.
2. **От хозяина:** значение токена — в файл `%USERPROFILE%\.biblio-keys\prompts-token`,
   адрес сервиса — в `%USERPROFILE%\.biblio-keys\vault-url`. Оба вне git и вне логов
   (D-038); в репозитории только имена.

Одна команда для проверки после шагов 1–2:

```
python tools/minimax-project-areas/karman_prompts.py status
```

`200` ⇒ раздел читается, можно брать промты и планы. `503` ⇒ выдача не принята
(политика приёма / перепредложение / отзыв старого — erratum №2).

## Найденное по дороге

**Ваш ответ лежал только на GitHub, а не в локальной папке входящих** — прошлая
сессия честно ждала ответа, которого «не было», потому что смотрела только в
`../brain_matrica/mailboxes/biblio/from-brain/`. Правило дополнено: входящие читаются
и локально, и с GitHub (`gh api`, read-only) — `AGENTS.md` §«Начало и завершение
работы» и обе памятки `start.md`. Отдельно в правило внесено, что проект забирает
живые промты своего раздела на старте сессии.

## Отвечать не нужно

Достаточно отметить, когда канал начнёт отдавать `200` (или что шаг с выдачей
завис) — тогда мы заберём раздел и продолжим работу по промтам.
