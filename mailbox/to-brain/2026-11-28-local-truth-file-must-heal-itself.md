# Коротко

1. **Локальный файл, который есть источник правды, обязан сам восстанавливаться.**
   Конфиг областей «МиниГена» (`mcode-project-areas.json`) — **чисто локальная
   вещь машины**: в git его нет (канон владельца 27.11), и единственная
   страховка — копия рядом. На живой машине файл **пропал** — и программа
   полдня показывала «0 областей», молча стояла надзором и **создание агента
   область не заводило**. Теперь программа чинит список сама при старте (по
   копии и по каталогам данных), а в окне есть кнопка «Починить список».
2. **Запись, которая сокращает список, — это потеря, а не замысел.** Если
   сущности **никогда не удаляются** (области не удаляются ни одной командой),
   то любая запись с меньшим списком — дефект. Такая запись не пишется вовсе.
   Правило переносимое: *«программа, которая ничего не удаляет, обязана
   отказываться уменьшать свой список»*.
3. **Ловушка Python: `cfg.get("projects") or []` съедает `append`.** При
   **пустом** списке `or` даёт **новый** список, и `projects.append(...)`
   уходит во временный, а в файл пишется пусто. Список остаётся пустым —
   и **ни одна** область не заводится никогда (ловушка, которая не выпускает).
   Правило: *список, который собирают для записи, **пересобирают и кладут
   обратно**; мутировать список, взятый через `or []`, нельзя*.
4. **Две таблицы об одной сущности — две правды, и одна из них вредит.**
   В окне были вкладки «Области» и «Агенты», и они показывали разное: агент,
   созданный в «Агентах», **не появлялся** в «Рабочих областях» ⇒ владелец
   решил, что программа не работает. Заказ владельца: «Области» и «Агенты» —
   одно и то же, это «Агенты». Сведено в одну таблицу: строка — **область**,
   агент — её содержание. Переносимо: *если два экрана показывают одну
   сущность, их надо **свести в один** — иначе расхождение двух экранов
   читается как поломка программы*.
5. **Сторож, который «держит последний рабочий», обязан говорить правду.**
   Демон писал «не читается — держу последний рабочий», а рабочего **не
   было** (демон перезапустили) ⇒ надзор стоял молча. Теперь сообщение
   называет, есть ли рабочая копия, а пустой список областей считается
   **разбором**, а не «нечитаемым конфигом».

# 3. Что переносимо (для «Мозга» и других программ)

1. **Файл-источник правды, который живёт только на машине, обязан иметь путь
   восстановления** — иначе его потеря молча превращается в «программа не
   работает». Три источника восстановления: копия рядом, факты на диске,
   внешний реестр (GitHub).
2. **Программа, которая ничего не удаляет, обязана отказываться уменьшать
   свой список** — это ловит потерю на записи, а не после.
3. **Проверка «починил ли код» на сломанной копии** — обязательный шаг приёмки:
   приёмка, которая проходит и на старом коде, не проверяет ничего.
4. **Расхождение двух экранов об одном сущности читается владельцем как
   поломка** ⇒ экраны сводят в один, а не «чинят по очереди».

# 4. Открыто владельцу

- **Раскатка — за владельцем** (как всегда): правка в репозитории, на живой
  машине — после раскатки.
- **На этой машине нет `~/.brain_matrica/secrets.env`** ⇒ клиент КАРМАНА не
  знает адреса хранилища и токена: **пул аккаунтов и канал промтов не
  работают** (вход в область придётся брать руками — «Новый вход»). Это
  отдельная потеря локального состояния машины, не дефект программы.
