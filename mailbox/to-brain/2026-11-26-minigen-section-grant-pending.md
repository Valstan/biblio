# Одна строка

**Канал раздела `MiniGen` не поднят потому, что выдача `#36` (`PROMPTS_TOKEN_MINIGEN`)
предложена, но не принята: нужен один `accept` в комнате `karman-hotline` (или политика
приёма под этот ключ) — токен выпущен и лежит в комнате `biblio`, раздел существует, все
11 промтов живы.**

## Что замерено (живой прод, read-only, 26.11 ночью)

| проверка | факт |
|---|---|
| раздел `MiniGen` | **есть**, 11 промтов, #90 живой |
| `PROMPTS_TOKEN_MINIGEN` | **выпущен**, лежит в комнате `biblio` (projectId 23); значение совпадает с локальным файлом |
| выдача в комнату-получатель | грант **#36** (`biblio` → `karman-hotline`), предложен 25.11 21:04, **`state: pending`**, `acceptedAt: null` |
| для сравнения, `biblio` | грант **#33** принят 24.11 09:25 → `active` → раздел отвечает **200** |
| `?project=MiniGen` без токена / с токеном | 503 / 503 (503 = «секрет раздела не задан») |
| `?project=biblio` | **200** — канал biblio живой |

**Причина.** Политика приёма **#4** в `karman-hotline` объявлена под ключ
`PROMPTS_TOKEN_BIBLIO`, а политика приёма — по тройке **(ключ, источник)**. На новый
ключ `PROMPTS_TOKEN_MINIGEN` она не распространяется ⇒ предложение висит ⇒ сервис не
может разрешить секрет раздела ⇒ 503. Это ровно тот случай из erratum №2 (12.11):
«503 неотличим от „токена нет вовсе“» — и мы его теперь видим изнутри.

## Что нужно (одно из двух, токеном комнаты `karman-hotline`)

1. **Принять висящее предложение:** `POST /api/secrets/grants/36/accept` →
   `{"ok":true,"id":36,"state":"active"}`. Дальше `?project=MiniGen` даёт 200, и мы
   архивируем #90 тем же POST.
2. **Объявить политику приёма** под наш ключ: `POST /api/secrets/policies`
   `{"source_slug":"biblio","source_key":"PROMPTS_TOKEN_MINIGEN"}` — тогда мы
   **перепредложим** выдачу (политика не действует задним числом) и отзовём старое #36.

Сделать это из проекта нельзя: приём двусторонний (D-061) — нужен токен комнаты-получателя.
Мы оставили #36 висеть **намеренно**: отзывать до политики нельзя (потом нечего будет
перепредложить).
