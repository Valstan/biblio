# 1. История чата — на диске машины

- файл: `%LOCALAPPDATA%\minigen-gui\chat-history.json` — **вне репозитория**
  (D-038: в переписке бывают имена хостов, пути и ответы инструментов);
- формат: реплики `{role, text, calls, at}`; предел — **200 реплик или 1 МБ**,
  что наступит первым; запись атомарная (временный файл + замена);
- новая команда **`chat.history`** — окно читает переписку и восстанавливает её
  после перезапуска окна; **`chat.reset`** («Очистить») чистит и файл, и память;
- при перезапуске самой программы память Управляющего восстанавливается из
  видимой переписки (текстом): переписка на месте даже если программу
  перезапустили.

# 2. Переписка не теряется при смене вкладки

Причина была в окне: вкладка ставится условием, поэтому при уходе с неё
компонент размонтировался, а его `useState` с перепиской обнулялся. Теперь
состояние чата живёт **в общем месте окна** (модуль-стор, подписка через
`useSyncExternalStore`), а не в компоненте вкладки: ушёл на другую вкладку —
вернулся, переписка на месте.

# 3. Ответ — резюме, а не сырой JSON

- главное в реплике — **текст модели**;
- вызовы инструментов — свёрнутый блок **«Что сделано: N действий»**, раскрывается
  по клику; сырой JSON по умолчанию не виден;
- обрезка результата до 400 символов **убрана**: полные аргументы и полный
  результат доступны по требованию и не выбрасываются;
- живой пример с машины: последний ответ пробы — **40 действий** в одном
  свёрнутом блоке (поиск → чтение → ветка → правки → проверки → diff → коммит →
  PR), первый результат — 14 КБ текста, и он виден целиком по клику.

# 4. Отчёты сторожей — не реплики истории

Раньше сводка непрочитанных отчётов добавлялась в историю сообщений как реплика
«user» и оставалась там навсегда. Теперь это **подсказка хода**: она уходит в
системную подсказку и в историю **не попадает**. Проверено вживую: в истории
живой машины ровно одна реплика владельца — вопрос, который он задал.

# 5. Живая проба самоотладки (главное)

**Как шла.** Мост взят из **установленной** программы — тот же Управляющий, что
стоит у владельца, с живым аккаунтом, живым GitHub и живым клоном копии. Надзор
демонов и раздача промтов в пробе отключены (проба не трогает боевых демонов).
Задание — дословно из промта: «найди в исходниках программы настоящий дефект и
почини его своим ходом», с указанием идти по цепочке `code.*`.

**Проба №1 — не прошла, и это было важнее.** Управляющий отработал совет
специалистов, поиск, чтение и проверки — и остановился на «достигнут лимит
шагов». Причина оказалась **дефектом программы**, а не слабостью модели: бюджет
задачи был общим, и совет специалистов забирал его целиком — на саму работу
оставалось **4 шага**, а задача «найди и почини» по инструкции самой программы
требует ~10 вызовов. **Починили:** у совета теперь свой предел (16 раундов), а
работа получает все 24 — совет обсуждает, работа делает.

**Проба №2 — прошла** (852 с, 13 ходов):

| Шаг | Что сделано |
|---|---|
| `code.search`, `code.read` | найден дефект: `minigen_daemons.daemon_pids()` обещает «командная строка **заканчивается** именем скрипта», а запрос WMI отбирал по «**содержит**» (`-like '*minimax-sessionwatch.py'`) |
| `code.branch` | отдельная ветка `agent/minigen-fix-demon-opoznavanie-po-kontsu-komandnoi-st` |
| падающий тест | `test_daemon_pids_skips_one_shot_calls`: `[4242, 5150] != [4242]` — красные |
| `code.patch` | запрос WMI отдаёт «pid <TAB> командная строка», отбор перенесён в Python: новая чистая функция `is_daemon_command()` (имя скрипта **в конце** строки) |
| `code.tests` | **304 теста моста зелёные**, `all` — мост, приёмка панели, приёмка записи конфига зелёные |
| `code.diff`, `code.commit` | проверка diff, коммит в ветку |
| `code.pr` | **PR #161 открыт, проверка `gate` — SUCCESS** |

**Что это значит по существу.** Найденный дефект был не косметическим: разовый
вызов (`minimax-sessionwatch.py --list`) считался живым демоном, поэтому окно
показывало «демоны 3/3», когда демоны мёртвы, а «поднять демона» отвечало «уже
работает» и не поднимало ничего — демон молчал (лечащий не чинил аккаунты,
сторож сессий не ждал сессии). Прежний тест это не ловил: он составлял шаблон
**в самом тесте** и проверял его, а не код программы.

Отдельный отчёт: `tools/minigen-gui/docs/SELFDEBUG-REPORT.md`.
