Прими новое задание **по системе мозга проекта** (промт КАРМАНА #199). Порядок
жёсткий: **сначала поднять накопленный опыт, потом принимать решение о маршруте
и составе** — задание не разбирается заново с нуля.

**Промт:** <вставь текст задания>

1. **Поднять опыт проекта** (обязательный первый шаг):
   - `docs/SESSION_HANDOFF.md` — последние разборы (что по теме уже решали);
   - `mailbox/to-brain/` — переносимые правила;
   - `tools/minigen-gui/bridge/agent-templates/*/skills/` — повторяемые процедуры;
   - `tools/minigen-gui/docs/knowledge-pack.md` — что программа уже знает.
   Скажи вслух: что по этой теме **уже известно** и что из этого меняет план.
2. **Прочитать** `docs/brain/CONSTITUTION.md` (границы) и `docs/brain/LENS.md`
   (где что лежит), плюс `AGENTS.md`.
3. **Понять промт**: что просят и что считается «сделано». Неясность — вопрос
   владельцу, **не догадка**.
4. **Выбрать маршрут** и назвать причину:
   - **простая** (локально, понятно, без выбора, риск низкий) → «координатор →
     программист», совет не собирается;
   - **сложная или спорная** (незнакомый участок, есть выбор, спорно, риск
     разрастания) → разведчик → совет → программист.
5. **Выбрать состав** — по `docs/brain/registry.json`. По **каждой** роли сказать,
   зачем она здесь. Пределы: простая задача — 1 эксперт; совет по умолчанию
   ≤ 3 голосов; верхняя граница 6. Кого звать — по таблице в
   `docs/brain/INTAKE.md` §3.
6. **Написать план** в формате `шаг → ответственный → выход → проверка`.
   Шаг без проверяемого выхода — не шаг.
7. **Раздать работу по ролям** (`docs/brain/COUNCIL.md`): у каждой роли свой
   вход и свой выход. Переключение роли должно быть **видно в разборе**.
8. **Свести работу**: критик — вывод по коду и по плану; тестер — вердикт по
   стенду («решает задачу или уходит в тупик»); затем **сверка плана**
   (`docs/brain/INTAKE.md` §6): что не дописано — названо честно.
9. **Закрыть опыт** (второе хранилище не заводим):
   - разбор задачи → `docs/SESSION_HANDOFF.md`;
   - переносимое правило → `mailbox/to-brain/YYYY-MM-DD-*.md`;
   - повторяемая процедура → скилл в `tools/minigen-gui/bridge/agent-templates/*/skills/`;
   - **изменился проект** → обновить `docs/brain/LENS.md` и
     `docs/brain/registry.json` (правило «изменился проект — изменилась карта»);
   - проверка, доказывающая результат, — рядом с кодом.
10. **Проверить**: `python tools/minimax-project-areas/test_brain_system.py`
    (линза обязана совпадать с кодом) и гейты проекта, которых касалась правка.

Приёмка не подменяется: обычный порядок «ветка → PR → проверки, решение за
человеком» сохраняется. Секретные токены, пути машины и хостнеймы — мимо
репозитория (D-038).
